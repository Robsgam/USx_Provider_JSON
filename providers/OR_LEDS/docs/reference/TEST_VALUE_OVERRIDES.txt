# ── Middle name: a real name, not a single initial (2026-08-27) ─────────────────────────────────
# WHY: the default test value for nameMiddle was "A", a single letter, while the control is labelled
# "Middle Name" with maxLength=30. Every sweep would therefore have proven only that a ONE-CHARACTER
# middle name reaches the wire.
# Same gap Rob caught on NM_NMLETS_OFML by eye on 2026-08-27 ("is it a middle initial or middle name
# you are only entering an intital and the fields says name?"). Fixed here BEFORE OR's first sweep
# rather than after it, so the finding costs no re-run.
#
# WHY IT MATTERS AT WIDTH: the wire format is `LAST, FIRST MIDDLE SUFFIX` (FormatStringRuleHandler)
# and OR's `Name` is capped at 30 -- confirmed from BOTH sides, the QIDM attribute (size=30) and the
# raw metadata (<Field name="Name" maxLength="30">). A single initial can never exercise that cap, so
# a truncation defect at realistic width would be invisible to a green sweep.
#   before:  DOE, JOHN A JR         = 14 chars  (16 of the 30 unused)
#   after:   DOE, JOHN MICHAEL JR   = 20 chars  (inside 30 -- proves width WITHOUT forcing a
#                                                truncation failure, which is a separate and
#                                                deliberate test)
# nameSuffix is left at "JR": the control is maxLength=5, so "JR" already exercises it sensibly and a
# longer value would test nothing the field can hold.
nameMiddle=MICHAEL

# ── Plate-type TOGGLE: must differ from the form default, or the test proves nothing ────────────
# emit_test_plan reported: "Vehicle any[]: 'LicensePlateTypeCode' toggle value 'PC' == form default
# 'PC' -- hollow toggle test". The _af_ test existed to prove the officer can CHANGE the plate type
# and that the change reaches the wire; toggling PC to PC proves only that the default is the
# default. Standing rule: a toggle fill must differ from the form default.
#
# VALUE TAKEN FROM THE TENANT, NOT GUESSED. Plate-type contents are TENANT data -- the same
# category/source pair holds different codes per tenant -- so this was left unset until the one-time
# picklist scope ran (2026-08-27, 64 options captured for NCIC_LICENSE_PLATE_TYPE/NCIC). Guessing a
# code the tenant does not offer would have failed at the dropdown mid-sweep, which is a worse
# failure than the hollow test it replaced, and with no TENANT_PICKLISTS.json the picklist gate
# could not have caught it.
# TK chosen over the other 63: it is unambiguously distinct from PC (regular passenger automobile)
# and is the plate type most likely to change a real-world match, so a wire difference here is
# meaningful rather than cosmetic.
LicensePlateTypeCode.toggle=TK
