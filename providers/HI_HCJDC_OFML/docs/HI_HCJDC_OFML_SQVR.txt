  - NIBRS sex reverse-lookup (codeTypeProvider=NIBRS)

  - Name format: 4 components (First Last Middle Suffix) with space separators
  - Date format: MMddyyyy

1. VehicleRegistrationQuery -- Vehicle Entity
================================================================================

  QIDM: VehicleRegistrationQueryQIDM
  QIF:  Vehicle (3 cards: SEARCH OPTIONS / PLATE SEARCH / VIN SEARCH)
  Combos (v3.0+ OOS-first order): RQ (OOS plate), RQV (OOS VIN),
          M55L (in-state plate), M55S (in-state VIN), QVV/QVP (stolen, dormant)
  Optional fields: VehicleMakeCode, VehicleYear, ImageIndicator,
                   VehicleTypeCode (default=1, Auto)
  Routing principle (v3.0+): out-of-state is reached by ADDING fields, never by
    clearing Vehicle Type. Plate discriminator = Plate Type/Year presence; VIN
    discriminator = State presence. First-match firing on combos ordered OOS-first.

  RQ -- OOS plate (Plate + PlateType + PlateYear) [CONFIRMED]
    set: LicensePlateNumber, LicensePlateTypeCode, LicensePlateYear
    any: ImageIndicator, RegistrationState
    keyReference: RQ
    Fires when: Plate Type AND Plate Year filled (the OOS-plate signal). State
      rides along via any[]. VehicleTypeCode does NOT bleed (M55L's
      LicensePlateTypeCode NOT_EXISTS condition exits it from the union pool).
    Live v3.4 T4: Plate=ABC123 + PlateType=PC + PlateYear=2020 + State=CA ->
      XML LicensePlateNumber/LicensePlateTypeCode/LicensePlateYear/State=CA/Image=N,
      VehicleTypeCode ABSENT. RMS registrationStateAttrIds+tag.

  RQV -- OOS VIN (VIN + State) [CONFIRMED]
    set: VehicleIdentificationNumber, RegistrationState
    any: ImageIndicator
    keyReference: RQV
    Fires when: VIN + State filled (State is the VIN OOS discriminator, in set[]).
      VehicleTypeCode does NOT bleed (M55S's RegistrationState NOT_EXISTS condition
      exits it from the union pool).
    Live v3.4 T5 (DECISIVE): VIN=233HNFHFG783634 + State=CA -> XML VIN/State=CA/Image=N,
      VehicleTypeCode ABSENT. Proves conditions[].field = sourceField
      (RegistrationState); v3.2 used field=State (attribute name) and VehicleTypeCode
      BLED. RMS registrationStateAttrIds+vinNumber.

  M55L -- in-state plate (VehicleTypeCode + Plate) [CONFIRMED]
    set: vehicleTypeCode, LicensePlateNumber
    any: ImageIndicator, RegistrationState
    conditions: LicensePlateTypeCode NOT_EXISTS (exits pool for OOS plate / RQ)
    keyReference: M55L
    Fires when: bare Plate present (Vehicle Type defaults to 1=Auto, auto-satisfying
      the server's in-state requirement). Defaults: VehicleTypeCode=1, ImageIndicator=N.
    Live v3.4 T2: Plate=ABC123 -> XML LicensePlateNumber/VehicleTypeCode=1/Image=N.

  M55S -- in-state VIN (VehicleTypeCode + VIN) [CONFIRMED]
    set: vehicleTypeCode, VehicleIdentificationNumber
    any: ImageIndicator
    conditions: RegistrationState NOT_EXISTS (exits pool for OOS VIN / RQV)
    keyReference: M55S
    Fires when: bare VIN present, no State. Defaults: VehicleTypeCode=1, Image=N.
    NOTE: RegistrationState removed from any[] in v3.4 -- it can never serialize
      alongside M55S (M55S only fires when State absent), and its presence in any[]
      caused the test conductor to inject State and falsely block M55S (v3.3 T16 FAIL).
    Live v3.4 T3: VIN=1HGNM8363783 -> XML VIN/VehicleTypeCode=1/Image=N, no State.

  QVV -- stolen VIN (VIN + VehicleMakeCode) [DORMANT]
    set: VehicleIdentificationNumber, VehicleMakeCode
    any: ImageIndicator, RegistrationState
    keyReference: QVV
    DORMANT by design: ordered last; shadowed by M55S/RQV for any VIN entry. The
      state CommSys server auto-generates the QV/stolen query from supplied fields
      (response data-mined via QRDM). Not directly live-fireable from the form.

  QVP -- stolen plate (Plate + State) [DORMANT]
    set: LicensePlateNumber, RegistrationState
    any: ImageIndicator
    keyReference: QVP
    DORMANT by design: ordered last; shadowed by RQ/M55L for any plate entry.
      Server auto-generates QV/stolen (QRDM data-mined). Not live-fireable from form.

  Priority order: RQ > RQV > M55L > M55S > QVV > QVP -- CONFIRMED (note; backed by live v3.4 T2-T5)
    OOS-first (add fields to reach OOS); in-state plate/VIN next; stolen dormant last.
    Each combo fired as expected on first match (T2-T5).

  APPROVED SKIP -- generic QV catch-all (by LicensePlateNumber / by VIN):
    The 2 generic QV combos in metadata are intentionally NOT built as standalone
    user combos; stolen lookup is server-generated (QVV/QVP dormant + QRDM).
    Confirmed not-to-build (user, 2026-06-22). Not a coverage gap.

  OOS routing -- reached by adding fields -- CONFIRMED (note; backed by live v3.4 T2-T5)
    Plate: bare -> M55L (in-state); +PlateType+PlateYear -> RQ (OOS). VIN: bare ->
    M55S (in-state); +State -> RQV (OOS). Live v3.4 T2/T4 (plate), T3/T5 (VIN).
    Both OOS combos emit clean XML with NO VehicleTypeCode bleed (NOT_EXISTS conditions).

  RMS co-fire -- CONFIRMED (note; backed by live v3.4 T2-T5)
    RMS Vehicle fired alongside CommSys on all v3.4 Vehicle tests (elasticQuery:
    tag / vinNumber / registrationStateAttrIds). Live v3.4 T2-T5.
