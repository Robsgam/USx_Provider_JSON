LESSONS FROM PRIOR BUILDS (applied in Phase 1 reboot)
------------------------------------------------------
Phase model: Phase 1 (single card) confirmed all QIDMs before Phase 2 (multi-card UX).
  NJ and NY v1.x built multi-card / split-entity before QIDMs were confirmed.
  Failures were impossible to isolate. Single-card Phase 1 eliminates layout as a variable.

LIMITATION #2 (platform evaluates only ONE QIDM per (targetEntity, query) pair):
  Discovered NJ v2.6, confirmed NY v1.11. Split configs silently ignored.
  Vehicle QIDM: merged RVEH+RVIN+RCAR into single QIDM (all distinct keyRefs).
  DL: DLIC (OLN) + DGRP (separate transaction NyNyspinDriverLicenseNameQuery) -- no conflict.
  DH: DALL+DALH in single QIDM (DALH = invented distinct keyRef). Confirmed v1.19.

DH-suffix fieldIds: OperatorLicenseNumberDH, NameFirstDH, NameLastDH, NameMiddleDH,
  NameSuffixDH, BirthDateDH, SexCodeDH. Confirmed v1.17/v1.19. Do not rename.

WINQ/MINQ: discovered not to have Transaction XML definitions -- excluded from Phase 1.

State dual-field: NCIC codeTypeProvider unconfirmed on NY instance. Using NJ_NIBRS_STATE
  (blank-default) + hidden SelH RegistrationState (initialValue=NY). Test NCIC on Phase 1 import.

Sex NIBRS_SEX CommSys-only: NIBRS reverse-lookup unconfirmed on NY instance.
  Using codeTypeCategory=NIBRS_SEX (stores text M/F/U). No codeTypeProvider in CommSys QIDM.
  Sex removed from RMS person QIDM entirely. Same pattern as FL_FCIC.
