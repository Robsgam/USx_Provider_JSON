STATE FIELD ARCHITECTURE (NY_NYSPIN_EJUSTICE-specific)
================================================================================

  NY in-state forms (Vehicle - NY, Person - NY):
    Field 1: SelH  fieldId='RegistrationState'    attributeTypeId='STATE'  initialValue='NY'
             -- Hidden. Sends internal attribute ID (69509802469) to RMS elastic search.
             -- NOT in QIDM. Never reaches outbound XML.
    Field 2: InpH  fieldId='RegistrationStateNY'  initialValue='NY'
             -- Hidden. QIDM sourceField for RegistrationStateNY attribute. Sends 'NY' to XML.

  OOS forms (Vehicle - Out of State, Person - Out of State, Boat):
    Field:   Sel   fieldId='RegistrationStateOOS'  codeTypeCategory='NJ_NIBRS_STATE'
                   codeTypeSource='NJ_NIBRS'
             -- Visible dropdown. Sends 2-letter state code to outbound XML.
             -- No attributeTypeId -- does not interact with RMS attribute lookup.

  Boat form:
    Field:   Sel   fieldId='RegistrationStateOOS'  codeTypeCategory='NJ_NIBRS_STATE'
                   codeTypeSource='NJ_NIBRS'
             -- Visible dropdown, no initialValue. Blank = NY (RVEH/RCAR fires).
             -- OOS state selected = BVEH/BVIN fires.

  Why this matters:
    attributeTypeId='STATE' on any FormSelect causes the platform to send the
    internal numeric attribute ID (e.g., 69509802469 for NY) instead of the 2-letter code.
    This is correct for RMS elastic search but wrong for outbound XML.
    codeTypeCategory='NJ_NIBRS_STATE' sends the 2-letter code -- safe for outbound XML.
    This is the same dual-field pattern confirmed in NJ_NJCJIS testing (2026-04-10).

================================================================================
PLATFORM BEHAVIOR NOTES (NY-specific)
================================================================================

  1. NJ_NIBRS_STATE is an NJ-specific code list reused for NY state dropdowns.
     Confirmed to send 2-letter state codes in both NJ and NY testing (2026-04-13).
     No NY-specific state code list identified in platform; NJ_NIBRS is the working approach.

  2. attributeTypeId='STATE' always sends an internal numeric ID, not a 2-letter code.
     Only use on hidden SelH fields for RMS; never map in QIDM for outbound XML.
     NY state attribute ID = 69509802469 (confirmed in Test 1 RMS output).

  3. ImageIndicator is FormInput (free-text Y or blank) rather than FormSelect YES_NO_UNKNOWN.
     Y-only fields use FormInput to prevent N/U appearing in dropdown.

  4. SexCode uses NIBRS_SEX / NIBRS (sends M/F/U). Fixed v1.2 from attributeTypeId=SEX
     (which sent numeric attribute ID -- same issue as STATE).

  5. ArticleTypeCode codeTypeSource = CA_CLETS (not NCIC). Same as NJ and FL patterns.
     NCIC_ARTICLE_TYPE lives under CA_CLETS in the platform.

  6. RaceCode uses attributeTypeId='RACE' -- UNCONFIRMED. Risk: sends numeric ID to XML.
     Test WantedPersonQuery/MissingPersonQuery dropdown to confirm population.
     Fallback: change to FormInput maxLength=1.

  7. LIMITATION #2 applies to DL/DH split configs (_OLN/_Name).
     Platform evaluates only ONE QUERYINPUTDATAMAPPING per (targetEntity, query) pair.
     DL/DH cannot be merged (duplicate keyReference DLIC/DALL).
     Monitor cold-start failures on the secondary (Name) path in live testing.
