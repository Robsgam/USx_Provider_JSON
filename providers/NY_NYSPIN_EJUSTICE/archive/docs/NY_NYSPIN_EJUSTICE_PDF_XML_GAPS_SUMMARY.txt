NY NYSPIN_EJUSTICE -- DevDoc vs MetaData Discrepancies
=======================================================
Date   : 2026-04-13  (updated v1.11 -- live testing in progress)
Source : NY_NYSPIN_EJUSTICE DevDoc  -- "New York (NYSPIN_XML).pdf"
         NY_NYSPIN_EJUSTICE MetaData -- NY_NYSPIN_EJUSTICE.XML (v8)

The following discrepancies remain between the DevDoc specification
and the ConnectCIC provider MetaData.  Previously-resolved gaps are
noted at the end.

--------------------------------------------------------------------------------
1. DRIVERHISTORYQUERY -- COMBINATION STRUCTURE
--------------------------------------------------------------------------------

  DevDoc  : 4 explicit combinations:
              1. (In)  BirthDate, Name, SexCode, [ImageIndicator, NyNyspinTransactionName]
              2. (In)  OperatorLicenseNumber, [ImageIndicator, NyNyspinTransactionName]
              3. (Out) BirthDate, Name, PurposeCode, Requestor, SexCode, State, [ImageIndicator,
                       NyNyspinTransactionName]
              4. (Out) OperatorLicenseNumber, PurposeCode, Requestor, State, [ImageIndicator,
                       NyNyspinTransactionName]

  MetaData: 2 DALL combinations, each using a Choice structure:
              OLN combination  : Choice([OLN], [OLN+PurposeCode+Requestor+State])
                                 plus any[ImageIndicator, NyNyspinTransactionName]
              Name combination : Choice([Name+DOB+SexCode], [Name+DOB+SexCode+PurposeCode+
                                 Requestor+State])
                                 plus any[ImageIndicator, NyNyspinTransactionName]

  Implication: The MetaData treats in-state and out-of-state as a single combination with
  optional state fields.  DevDoc treats them as distinct paths where PurposeCode, Requestor,
  and State are required on out-of-state queries.

  Please confirm the intended handling of PurposeCode, Requestor, and State on out-of-state
  DriverHistoryQuery submissions.

--------------------------------------------------------------------------------
2. DRIVERLICENSEQUERY -- STATE FIELD OPTIONALITY
--------------------------------------------------------------------------------

  DevDoc  : State is required on out-of-state combinations:
              3. (Out) BirthDate, Name, SexCode, State, [ImageIndicator]
              4. (Out) OperatorLicenseNumber, State, [ImageIndicator]

  MetaData: State is listed in any[] (optional) in both DLIC combinations:
              OLN combo: OperatorLicenseNumber (set), any[ImageIndicator, State]
              Name combo: BirthDate+Name+SexCode (set), any[ImageIndicator, State]

  Implication: MetaData would allow an out-of-state query to be submitted without State.
  Please confirm whether State should be required for out-of-state DriverLicenseQuery
  submissions, and whether the MetaData should be updated to enforce this.

--------------------------------------------------------------------------------
3. MESSAGEKEY CONFLICTS -- RVEH AND RCAR SHARED BETWEEN TRANSACTIONS
--------------------------------------------------------------------------------

  The following keyReferences are shared between multiple transactions in the MetaData:

    RVEH  -- used by both VehicleRegistrationQuery and BoatQuery
    RCAR  -- used by both VehicleRegistrationQuery and BoatQuery

  VehicleRegistrationQuery uses RVEH for plate queries and RCAR for NY VIN queries.
  BoatQuery uses RVEH for NY boat registration queries and RCAR for NY boat hull queries.

  Live testing (2026-04-13) has confirmed RVEH fires correctly for vehicle plate queries
  (Test T1, T3).  BoatQuery routing has not yet been tested.

  Please confirm the intended routing behavior when RVEH or RCAR fires and both Vehicle
  and Boat transactions are active.  The platform disambiguates by targetEntity (Vehicle
  vs. Boat); please confirm this is CommSys-supported behavior.

--------------------------------------------------------------------------------
4. BOATQUERY -- RCAR STATE FIELD ON OUT-OF-STATE HULL PATH
--------------------------------------------------------------------------------

  DevDoc  : BoatQuery Out combination for hull ID requires State:
              3. (Out) BoatHullIdNumber, State [ImageIndicator]

  MetaData: keyRef=RCAR -- set=[BoatHullIdNumber], any=[ImageIndicator]
            State is not present in the RCAR combination.

  Implication: An out-of-state hull query can fire without State per MetaData, but DevDoc
  states State is required to route out-of-state.

  Please confirm whether State should be added to the RCAR combination for BoatQuery, or
  whether the MetaData correctly reflects that State is optional on this path.

--------------------------------------------------------------------------------
PREVIOUSLY-RESOLVED GAPS (updated 2026-04-13)
--------------------------------------------------------------------------------

  GunQuery fields -- RESOLVED
    Old gap: DevDoc documented GunCaliber, GunMake, and RelatedHitSearchIndicator as
    optional fields; old MetaData instead required FirearmCategoryCode and ReasonCode
    and included MiscellaneousDescriptiveText and PersonPropertyInSightIndicator (none of
    which appeared in DevDoc).
    Status: New MetaData and new DevDoc now agree.  GunSerialNumber is required; GunCaliber,
    GunMake, and RelatedHitSearchIndicator are optional.  Build updated accordingly (v1.7).
    Note: standalone GunQuery transaction is not yet confirmed in MetaData; vendor
    confirmation still needed before live testing.

  VehicleRegistrationQuery combination structure -- RESOLVED
    Old gap: DevDoc documented 4 combinations (in-state plate, in-state VIN, OOS plate,
    OOS VIN); old MetaData had 2 combinations (RVEH with Choice, RVIN for OOS VIN) with
    no separate NY VIN keyReference.
    Status: New MetaData adds RCAR for NY VIN (VehicleIdentificationNumber only, no state)
    and retains RVEH (in-state plate or OOS plate) and RVIN (VIN + State, OOS).  New DevDoc
    lists the same 4 paths explicitly.  The 4 query paths are now fully covered.
    Live test confirmation (2026-04-13):
      T1 -- RVEH NY plate:  PASS.  XML: State + LicensePlateNumber.
      T2 -- RCAR NY VIN:    PASS.  XML: VehicleIdentificationNumber only (no State).
      T3 -- RVEH OOS plate: PASS.  XML: LicensePlateNumber only (no State -- correct
            per DevDoc Choice option 1; State not required when plate alone is sufficient).
      T4 -- RVIN OOS VIN:   In progress.
