Architecture notes:
  - 6 basic queries (VehReg / DL / DH / Gun / Article / Boat), 30 CommSys combos, 5 QIFs
  - Combo array order follows the devdoc "Possible Combinations" listing order in every QIDM
    (v4.7 standard): in-state combos first, OOS/stolen combos later, reached by first-match.
  - Routing conditions are EXISTENCE-ONLY (State NOT_EXISTS/EXISTS, OLN NOT_EXISTS,
    RelatedHit NOT_EXISTS/EXISTS, Hull NOT_EXISTS). POISONED-ARRAY RULE (QIDM_REFERENCE Sec 2a,
    live-proven v4.9 T-A/T-B): any value comparison (EQUALS/NOT_EQUALS) disables the WHOLE
    conditions array -- all value-comparison conditions were removed. LIMITATION #1: the
    serialization pool is the union of set[]+any[] of ALL matching combos; existence conditions
    keep later combos out of the pool so a fully-filled card sends only the firing path's fields.
  - conditions[].field = QIF sourceField (form fieldId), NOT the attribute name -- a wrong/
    attr-name token is silently inert (verify_build CHECK 13; live-proven HI v3.3 / FL v6.4).
  - Identifier-priority guardrails complete: Plate>VIN (Vehicle), OLN>Name (DL + DH),
    Hull>Reg (Boat, all 3 families).
  - PascalCase USx fieldIds (native, v5.2). Name = Last-first comma-space "Last, First" (v6.1).
    Date = yyyyMMdd (CommsysParseDateRuleHandler). State = NCIC dropdown, no initialValue (LIMIT #30).
    Attention = auto-populated via CommsysGetLastNameFirstNameInitialRuleHandler (no visible field).
  - DL/DH: one-directional/opt-in queriesToDeselect; DH-suffix fieldIds; DH is OUT-OF-STATE ONLY.
