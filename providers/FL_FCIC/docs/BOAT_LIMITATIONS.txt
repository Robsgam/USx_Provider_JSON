FL_FCIC -- Boat Query Limitations & Resolution
=================================================
Date: 2026-05-01 (original)
Updated: 2026-05-05 (RESOLVED)

THE ORIGINAL PROBLEM (v3.0, pre-fix)
--------------------------------------
Our BoatQuery QIDM has 12 combos across 3 keyRef groups:
  BQ  = Nlets OOS boat registration (requires State)
  FBQ = FL FCIC boat registration (DHSMV, in-state)
  QB  = NCIC stolen boat query

QB+Hull and QB+Reg combos were UNREACHABLE because FBQ+Hull and FBQ+Reg
shared the same set[] primary field (BoatHullIdNumber / RegistrationNumber)
and fired first due to combo ordering. LIMITATION #3 (first match fires)
meant QB+Hull and QB+Reg could never be selected.

WHY VEHICLE DOESN'T HAVE THIS PROBLEM
--------------------------------------
Vehicle has TWO separate query types in the CommSys metadata:
  - VehicleRegistrationQuery -- holds FRQ/RQ combos (one QIDM)
  - VehicleStolenQuery -- holds QV combos (separate QIDM)

Both QIDMs evaluate independently, which is why we see co-fire (FRQ + QV both
send requests simultaneously). This is the ideal pattern.

WHY BOAT HAD THIS PROBLEM
---------------------------
The CommSys metadata only defines ONE query type for boats: BoatQuery. There is
no BoatStolenQuery. So all 12 combos (BQ + FBQ + QB) are in ONE QIDM.
Only the first match fires -- no co-fire possible within a single QIDM.

THE FIX -- RelatedHitSearchIndicator Routing (FL-8)
=====================================================
Date: 2026-05-05
Fallback tag: FL_FCIC_PRE_QB_ROUTING (commit 0e5ea98)

APPROACH:
We identified RelatedHitSearchIndicator in the FL metadata as a field exclusive
to the QB (NCIC stolen) transaction. It appears in QB combo any[] arrays but
NOT in any BQ or FBQ combo. This makes it an ideal routing toggle.

WHAT WE CHANGED:

1. Added RelatedHitSearchIndicator as a form field:
   - Location: ROW_BOA_3 (row 3, alongside NCICNumber, PCN, ImageIndicator)
   - Type: FormInput (text, maxLength=1)
   - Label: "Stolen Search (Y)"
   - Officer types Y to route to NCIC stolen; blank = FL registration

2. Added RelatedHitSearchIndicator as a QIDM attribute:
   - name: RelatedHitSearchIndicator
   - size: 1
   - sourceField: ['RelatedHitSearchIndicator']
   - targetField: RelatedHitSearchIndicator

3. Promoted RelatedHitSearchIndicator from any[] to set[] on QB+Hull and QB+Reg:
   - QB+Hull: set = [BoatHullIdNumber, RelatedHitSearchIndicator]  (was: [BoatHullIdNumber])
   - QB+Reg:  set = [RegistrationNumber, RelatedHitSearchIndicator] (was: [RegistrationNumber])

4. Reordered combos -- QB+Hull and QB+Reg BEFORE FBQ+Hull and FBQ+Reg:
   Old order: BQ(3) -> FBQ(4) -> QB(5)
   New order: BQ(3) -> QB+Hull -> QB+Reg -> FBQ(4) -> QB+CG/NCIC/PCN(3)

   QB+Hull is now evaluated BEFORE FBQ+Hull. When RelatedHitSearchIndicator=Y,
   QB+Hull's set[] is satisfied (Hull + Stolen flag) and it fires. When Stolen
   is blank, QB+Hull's set[] fails (missing RelatedHitSearchIndicator) and
   evaluation continues to FBQ+Hull, which fires as before.

WHY THIS WORKS:
- RelatedHitSearchIndicator is metadata-native (not invented)
- It appears ONLY in QB combos in the original metadata
- Promoting it to set[] creates an explicit differentiator between QB and FBQ
- FBQ combos don't require it, so blank Stolen = FBQ fires (unchanged behavior)
- BQ combos still fire first when State is present (BQ ordered before QB)

COMBO ORDER (all 12, final):
  #   keyReference               set[]                                          any[]
  --  -------------------------  ---------------------------------------------  ---------------------------------
   1  BQName                     BirthDate, NameLast, NameFirst, State          HullId, Reg
   2  BQBoatHullIdNumber         HullId, State                                  Reg
   3  BQRegistrationNumber       Reg, State                                     HullId
   4  QBBoatHullIdNumber         HullId, RelatedHitSearchIndicator              ImageIndicator, Reg
   5  QBRegistrationNumber       Reg, RelatedHitSearchIndicator                 ImageIndicator, HullId
   6  FBQBoatHullIdNumber        HullId                                         Decal, Reg, TitleLien, ImageInd
   7  FBQRegistrationNumber      Reg                                            HullId, Decal, TitleLien, ImageInd
   8  FBQDecalNumber             Decal                                          HullId, Reg, TitleLien, ImageInd
   9  FBQTitleLienInformation    TitleLien                                      HullId, Decal, Reg, ImageInd
  10  QBCoastGuardDocumentNumber CoastGuardDocumentNumber                       ImageIndicator
  11  QBNCICNumber               NCICNumber                                     ImageIndicator
  12  QBProcessControlNumber     ProcessControlNumber                           ImageIndicator

ROUTING LOGIC:
  State filled?       -> BQ fires (Nlets OOS, combos 1-3)
  Stolen Search = Y?  -> QB fires (NCIC stolen, combos 4-5 for Hull/Reg, 10-12 for CG/NCIC/PCN)
  Neither?            -> FBQ fires (FL registration, combos 6-9)

CO-FIRE NOT POSSIBLE:
  All combos are in one BoatQuery QIDM. Only the first match fires per submission.
  If the officer wants both registration AND stolen results, they submit twice:
  once without Stolen=Y (FBQ or BQ), once with Stolen=Y (QB). This matches
  standard NCIC operational workflow (registration check then stolen check).

  Co-fire would require a separate BoatStolenQuery transaction type in the
  CommSys metadata (like VehicleStolenQuery exists for Vehicle). That query
  type does not exist today -- it's a platform gap, not a JSON limitation.

PLATFORM BEHAVIOR DISCOVERED:
  Test 14 revealed that any[] is NOT a minimum-one-required gate. When set[]
  is satisfied but no any[] field is populated, the combo still fires. The
  any[] array controls which optional fields serialize to XML, not whether
  the combo matches. This aligns with LIMITATION #1 (set/any control combo
  selection, not field sending) but is more permissive than documented.

FALLBACK PLAN:
  If the server rejects RelatedHitSearchIndicator in the XML payload:
  1. git checkout FL_FCIC_PRE_QB_ROUTING -- providers/FL_FCIC/
  2. Rebuild with build_fl_fcic.ps1 / build_fl_fcic_mc.ps1
  3. QB+Hull and QB+Reg revert to unreachable (3 QB combos still work via CG/NCIC/PCN)
