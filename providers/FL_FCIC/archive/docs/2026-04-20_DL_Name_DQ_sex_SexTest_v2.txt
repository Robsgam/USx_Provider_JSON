CONCLUSION
----------
FL's ConnectCIC instance does NOT perform the codeTypeProvider=NIBRS reverse-lookup
(attr ID -> NIBRS code "M"/"F"/"U") on the CommSys QIDM SexCode attribute.

The same configuration (attributeTypeId=SEX + codeTypeProvider=NIBRS) was confirmed
working on NJ_NJCJIS v1.1 (2026-04-17). This is an instance-specific difference.

FL sex decision: CommSys-only
  Form: codeTypeCategory=NIBRS_SEX (stores string "M"/"F"/"U")
  CommSys QIDM: codeTypeProvider=NIBRS (passes string through -> <SexCode>M</SexCode>)
  RMS QIDM: remove sexAttrId attribute entirely (Patch 3 equivalent)
