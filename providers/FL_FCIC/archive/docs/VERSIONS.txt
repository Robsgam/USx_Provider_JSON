  - QUERYRESULTDATAMAPPING cloned from HI_HCJDC_Results with name/provider changed to FL_FCIC

  - DriverHistoryQuery (KQ) shares Person entity with DriverLicenseQuery (FDQ/QW)
  - BoatHullIdNumber maxLength set to 62 per FL XML (vs 20 in NJ)

v1.4  2026-04-07  Driver License / Driver History mutual exclusion
                  Added autoSelect + queriesToDeselect to all four DL/DH mappings
================================================================================

BACKGROUND
  HIDLE.json (Hawaii template) revealed two fields absent from our Driver License
  and Driver History mappings: autoSelect and queriesToDeselect. These fields
  control whether a query type pre-selects itself in the UI and whether selecting
  it forces deselection of a conflicting query type.

  Discovery was triggered by a question about whether the Driver History checkbox
  could automatically deselect Driver License. The answer is yes -- via
  queriesToDeselect -- but only after inspecting HIDLE.json, where Hawaii uses
  the identical mapping pattern for the same two query types.

  Prior to v1.4, both Driver License mappings had no queriesToDeselect, and
  FL_FCIC_DriverLicenseQuery was also missing autoSelect entirely. Both Driver
  History mappings had neither field. This meant all four query types could be
  simultaneously active on the Person card with no mutual exclusion enforced.

WHAT autoSelect CONTROLS
  true  -- the combination indicator pre-selects itself when it lights (driver
           license queries fire automatically when fields are populated)
  false -- the combination indicator lights but does NOT pre-select; the user
           must explicitly click it to include it in the query (driver history
           is intentional, requires conscious operator choice)

WHAT queriesToDeselect CONTROLS
  When a query mapping becomes selected (manually or via autoSelect), any query
  type listed in queriesToDeselect is immediately deselected. This enforces
  mutual exclusion between Driver License and Driver History -- a user cannot
  accidentally submit both at the same time.

CHANGES MADE

  FL_FCIC_DriverLicenseOLN  (FDQ/DQ/QW + OLN):
    Added: autoSelect = true
    Added: queriesToDeselect = ["DriverHistoryQuery"]
    Note: autoSelect was already present; queriesToDeselect was missing.

  FL_FCIC_DriverLicenseQuery  (FDQ/QW/DQ + Name):
    Added: autoSelect = true        (was absent)
    Added: queriesToDeselect = ["DriverHistoryQuery"]

  FL_FCIC_DriverHistoryQuery  (KQ + Name):
    Added: autoSelect = false       (was absent)
    Added: queriesToDeselect = ["DriverLicenseQuery"]

  FL_FCIC_DriverHistoryOLN  (KQ + OLN):
    Added: autoSelect = false       (was absent)
    Added: queriesToDeselect = ["DriverLicenseQuery"]

HOW THE BEHAVIOR WORKS IN PRACTICE
  Scenario A -- User fills DL fields only (OLN or Name+DOB+Sex):
    FDQ/QW/DQ combination lights and auto-selects.
    DriverHistoryQuery is deselected (was not selected anyway).
    Result: Driver License query fires; Driver History does not.

  Scenario B -- User fills DL fields PLUS PurposeCode+Attention:
    Both Driver License AND Driver History combinations light.
    When the user clicks Driver History to select it, queriesToDeselect fires
    and removes Driver License from the active set.
    autoSelect=false means Driver History does not self-select -- user must
    consciously choose it. This is the intended workflow for KQ.

  Scenario C -- User fills only PurposeCode+Attention but not OLN/Name:
    Neither combination lights (KQ still requires OLN or Name).
    No query fires.

SOURCE
  Pattern confirmed from HIDLE.json (HI_HCJDC_DriverLicenseQuery and
  HI_HCJDC_DriverHistoryQuery). Hawaii uses the same autoSelect/queriesToDeselect
  pattern for the same query pair.

NO OTHER CHANGES
  No form fields, attributes, combinations, or other mappings changed.
  Total configuration count remains 25 (FL_FCIC) + 5 (ENTITIES) + 6 (RMS) = 36.
