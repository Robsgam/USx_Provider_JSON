FL_FCIC / ConnectCIC JSON Limitations
======================================
Last updated: 2026-04-07
Current version: 1.0 (full build from FL_FCIC.xml + HIDLE.json)

FORM LAYOUT LIMITATIONS
-----------------------
1. No conditional field visibility
   - Field/Row/Card nodes only support static hidden: true/false.
   - Cannot show or hide fields based on user input, checkbox selection, or query type.
   - Workaround: Single card with all fields visible; QUERYINPUTDATAMAPPING combinations
     handle query routing automatically based on what is populated.

2. No field styling
   - No font size, color, weight, or emphasis props on any node type.
   - Cannot highlight the most common query fields or de-emphasize optional ones.
   - Workaround: Field ordering and Card titles only.

3. No text/label component
   - Available components: Card, Row, FormInput, FormSelect, FormDate, FormCheckbox only.
   - There is no standalone text or label element.
   - Workaround: Use Card.props.title to display instructional text (comment card pattern).

4. Article Type dropdown requires CA_CLETS as codeTypeSource
   - NCIC_ARTICLE_TYPE code list lives under codeTypeSource: "CA_CLETS" in this system.
   - Using codeTypeSource: "NCIC" results in an empty dropdown.
   - Resolution: Set codeTypeSource: "CA_CLETS" on the ArticleTypeCode FormSelect (done in v1.0).

5. Firearm Make field uses FormInput (not FormSelect)
   - FL GunQuery has no GunCaliber field (unlike NJ_NJCJIS).
   - No confirmed code list backing for GunMake dropdown.
   - Resolution: Using free-text input with maxLength from XML spec.
   - Can be upgraded to FormSelect if a valid codeTypeSource/codeTypeCategory is confirmed.

6. Duplicate QUERYINPUTFORM cards if added to both ENTITIES and RMS bundles
   - Adding QUERYINPUTFORM to the RMS bundle causes each entity form to render twice.
   - Resolution: QUERYINPUTFORM belongs only in the ENTITIES bundle (provider=MARK43).
     The RMS bundle contains only backend configs (no form layouts).

7. Card title prop does not render HTML
   - The platform renders Card.props.title as literal text.
   - HTML tags such as <strong> appear verbatim in the UI.
   - Workaround: Use ALL CAPS for query/section names in card titles (plain text only).

FL_FCIC-SPECIFIC NOTES
-----------------------
8. FL uses FCIC-specific transaction keys (not standard NCIC keys)
   - VehicleRegistrationQuery: FRQ (not RQ/RQN)
   - DriverLicenseQuery: FDQ (DHSMV) + QW (FCIC/Nlets)  -- not DQ/DQN
   - DriverHistoryQuery: KQ (FL-only, not present in NJ_NJCJIS)
   - BoatQuery: FBQ (not BQ/BQN)
   - GunQuery: QG (same as NCIC standard)
   - ArticleSingleQuery: QA (same as NCIC standard)

9. DriverHistoryQuery (KQ) is FL-specific
   - No equivalent in NJ_NJCJIS or CA_ESUN.
   - Targets Person entity alongside DriverLicenseQuery.
   - Both KQ combinations require State (RegistrationState); FDQ does not.
   - Both DriverLicenseQuery and DriverHistoryQuery share the Person form.

10. DriverLicenseQuery has two distinct sub-systems
    - FDQ = DHSMV (Florida DMV) -- OLN or Name+DOB+Sex; no State required
    - QW  = FCIC/Nlets -- Name+DOB; OLN optional; no State required
    - Both sub-systems handled by a single QUERYINPUTDATAMAPPING with 3 combinations.

11. VehicleRegistrationQuery has no State requirement
    - All FRQ combinations are FL in-state only (DHSMV / DMVR).
    - State field not included in FL Vehicle form (unlike NJ which has RegistrationState).
    - DecalNumber is FL-specific (DMVR decal lookup); requires LicensePlateYear.

12. BoatHullIdNumber maxLength = 62 in FL XML (vs 20 in NJ_NJCJIS)
    - FL FCIC allows longer hull ID strings than NJ.
    - Form input and QUERYINPUTDATAMAPPING size set to 62.

13. FL XML includes both FL-specific keys and standard NCIC/Nlets keys in the same Transactions
    - FRQ (FL FCIC plate) and QV (NCIC stolen vehicle) and RQ (Nlets out-of-state) all appear
      in VehicleRegistrationQuery -- each key routes to a different system.
    - FBQ (FL FCIC boat) and QB (NCIC stolen boat) coexist in BoatQuery.
    - FDQ/QW (FL/FCIC DL) and DQ (Nlets out-of-state DL) coexist in DriverLicenseQuery.
    - Resolution: Where keys are different they can coexist in one mapping (valid).
      Where the same key appears multiple times, separate mappings required.

14. Vehicle RegistrationState has no default value (unlike Boat/Person which default FL)
    - FRQ (FL-only) does not require State; RQ (Nlets out-of-state) requires State.
    - Leaving RegistrationState blank triggers FRQ+QV combos (FL+NCIC checks).
    - Filling RegistrationState additionally triggers RQ (out-of-state Nlets check).
