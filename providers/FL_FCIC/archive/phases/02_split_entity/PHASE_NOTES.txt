CRITICAL DESIGN DIFFERENCE FROM v2.0
  v2.0 used OOS-suffix field IDs (OperatorLicenseNumberOOS, SexCodeOOS, etc.)
  This created duplicate targetFields in the DLQ QIDM, breaking codeTypeProvider.

  v2.3 uses SAME base field IDs on both FL and OOS forms.
  No OOS-suffix. No duplicate targetFields. DLQ QIDM unchanged (13 attrs, 6 combos).
  Routing works via RegistrationState presence:
    Person-FL: no State field → only FDQ/QW combos match
    Person-OOS: has State → DQ combos match when State filled
    Person-DH: DH-suffix fields + State(FL) → only KQ combos match

QIDM NOTES

  DHQ: 10 attrs, 2 combos, autoSelect=False (user manually selects on DH tab)
  RMS: Dead OOS-suffix attrs removed (was 16, now 11). DH-suffix attrs kept.
