AZ-SPECIFIC CONFIRMED BEHAVIORS
---------------------------------

1.  NCIC state pattern CONFIRMED (2026-04-20)
    Single visible Sel 'RegistrationState' (attributeTypeId=STATE, initialValue=AZ).
    CommSys QIDM: codeTypeProvider=NCIC converts attr ID to 2-letter code for outbound XML.
    RMS: useAttributeId=true + AttributeArrayWrapperRuleHandler handles any state including OOS.
    No dual-field architecture needed. Same pattern as NJ_NJCJIS v1.7.
    Test still pending (Phase 1 import confirmed forms render; queries PENDING).

2.  NIBRS sex pattern CONFIRMED (2026-04-20)
    attributeTypeId=SEX + codeTypeProvider=NIBRS on both form field and CommSys QIDM attribute.
    CommSys: <SexCode>M</SexCode> (not numeric attr ID).
    RMS: useAttributeId=true, NO ArrayWrapper, sex attr KEPT in RMS QIDM.
    Same pattern as NJ_NJCJIS. Do NOT remove sex from RMS QIDM (unlike NY Phase 1).

3.  BirthDate format: yyyyMMdd (NOT MMddyyyy)
    AZ provider expects yyyyMMdd in outbound XML.
    CommsysParseDateRuleHandler arguments = @('yyyy-MM-dd','yyyyMMdd').
    This differs from NJ/NY (MMddyyyy). Do not copy NJ/NY date handler arguments.

4.  type='BUNDLE' REQUIRED on both CommSys provider bundle and ENTITIES bundle
    Confirmed failure: AZ v2.1 and v2.2 -- bundles assembled without type='BUNDLE';
    platform silently ignored configs; forms did not render.
    Fixed in v2.3 / v1.0 Phase 1. Now enforced in BUILD_CHECKLIST.txt.

5.  ENTITIES order must be nested object, NOT flat array
    WRONG:  "order": ["Vehicle","Person","Firearm","Article","Boat"]
    RIGHT:  "order": {"default":[...],"CAD_DISPATCH":[...],"FIRST_RESPONDER":[...]}
    Confirmed failure: AZ v2.2 (flat array; forms did not render).
    Fixed in v2.3 / v1.0 Phase 1. Now enforced in BUILD_CHECKLIST.txt.

6.  QIF forms require provider='MARK43' (not 'AZ_AZDPS')
    Confirmed failure: AZ v2.0 -- QIF configs had provider='AZ_AZDPS'; forms did not render.
    Fixed in v2.1. Platform only renders QIFs with provider='MARK43'.
    Can be set at bundle level (ENTITIES bundle provider='MARK43') and omitted from individual QIFs.

7.  DH-suffix fieldIds required for DriverHistoryQuery isolation
    OperatorLicenseNumberDH, NameLastDH, NameFirstDH, NameMiddleDH, NameSuffixDH,
    BirthDateDH, SexCodeDH, StateDH.
    KQ/KQH QIDM references only DH-suffix sourceFields. DL QIDMs never reference DH-suffix.
    StateDH is a hidden InpH (initialValue='AZ', plain text -- no NCIC) because DH state is
    always AZ and is mandatory in KQ/KQH set[].

8.  Invented keyRefs resolve duplicate-keyRef problem (confirmed v1.0)
    XML has same keyRef for multiple paths in same transaction.
    Invented distinct keyRefs (ACVRV, DQN, DQSS, KQH, ACQBH, BQH, ACQWN, ACQMN) resolve.
    Provider does not validate keyRef -- routes by XML field content. Platform-internal only.
    Same pattern as NY_NYSPIN_EJUSTICE (DALL+DALH). Confirmed working.

10. dexStateUserId auto-populates BadgeNumber (confirmed design decision -- v1.1)
    BadgeNumber appears as required/optional in AZ_AZDPS query transactions.
    Design decision (2026-04-20): badge is auto-populated from officer RMS profile.
    Form: hidden InpH 'dexStateUserId' on each QIF; QIDM sourceField = @('dexStateUserId').
    CommsysGetDexStateUserIdRuleHandler in AUTHENTICATION config resolves it automatically.
    Badge field is NOT visible on any AZ form. No officer input required.
    Combination routing note: because dexStateUserId is always present, combinations that
    had 'BadgeNumber' in set[] (ACVR, ACQG, ACQA, ACQB, ACQBH, ACWL) now always see it.
    Routing for those paths depends on the other set[] fields, not badge presence.
    See FIELD_RULES.txt Section 5 and ANTI_PATTERNS.txt #20 for the general rule.

9.  LicensePlateYear has no elastic mapping in AZ RMS
    Removed from RMS Vehicle QIDM licensePlateIn combination any[] (PATCH 1).
    Present in CommSys QIDM any[] (sent to CommSys if filled; RMS ignores it).
