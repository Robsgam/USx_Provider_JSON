DESIGN DECISIONS
================================================================================

STATE (NCIC confirmed for AZ):
  Form: FormSelect fieldId='RegistrationState', attributeTypeId='STATE', initialValue='AZ'
  QIDM attr: sourceField=@('RegistrationState'), targetField='State', codeTypeProvider='NCIC'
  RMS: attributeTypeId=STATE attr ID passes through naturally via useAttributeId=True
  DH hidden state: InpH fieldId='StateDH', initialValue='AZ' (mandatory in KQ/KQH set[])

SEX (attributeTypeId=SEX + NIBRS confirmed for AZ):
  Form: FormSelect fieldId='SexCode', attributeTypeId='SEX', codeTypeProvider='NIBRS'
    -> stores attribute ID; NIBRS codeTypeProvider converts to 'M'/'F'/'U' for CommSys
  RMS: useAttributeId=True passes attribute ID directly -> sex filtering works
  DH form: same pattern but fieldId='SexCodeDH' (DH-suffix isolation)
  Wanted/Missing forms: same pattern (fieldId='SexCode')

RACE (NIBRS confirmed):
  Form: FormSelect fieldId='RaceCode', codeTypeCategory='NIBRS_RACE', codeTypeSource='NIBRS'
  QIDM attr: codeTypeProvider='NIBRS'
  NOT using attributeTypeId='RACE' (AP #3 -- sends numeric ID)

BIRTHDATE (AZ uses YYYYMMDD -- different from NJ MMddyyyy):
  arguments = @('yyyy-MM-dd','yyyyMMdd')

NAME FORMAT:
  FormatStringRuleHandler arguments = @(', ',' ',' ')
  sourceField order: NameLast, NameFirst, NameMiddle, NameSuffix
  Produces: "Last, First Middle Suffix"
  DH variant: NameLastDH, NameFirstDH, NameMiddleDH, NameSuffixDH

INVENTED keyRefs (provider routes by XML field content, not keyRef):
  ACVRV  VIN path of VehicleRegistrationQuery    (XML has ACVR for both paths)
  DQN    Name path of AzAzdpsDriverLicenseQuery  (XML has DQ for OLN/Name/SSN)
  DQSS   SSN path of AzAzdpsDriverLicenseQuery
  KQH    Name path of DriverHistoryQuery          (XML has KQ for OLN and Name)
  ACQBH  Hull+Badge path of BoatQuery             (XML has ACQB for Reg and Hull)
  BQH    Hull path of BoatQuery                   (XML has BQ for Reg and Hull)
  ACQWN  NCICNumber path of WMPIWantedPersonInquiry  (XML has ACQW x11)
  ACQMN  NCICNumber path of WMPIMissingPersonInquiry (XML has ACQM x2)

DH-SUFFIX ISOLATION (LIMITATION #26):
  DriverHistoryQuery uses OperatorLicenseNumberDH, NameLastDH, NameFirstDH,
  NameMiddleDH, NameSuffixDH, BirthDateDH, SexCodeDH, StateDH.
  These field IDs are absent from the DL form -- no cross-contamination of field pools.

LAYOUTS:
  MakeLayouts() helper builds default + CAD_DISPATCH + FIRST_RESPONDER variants.
  CAD_DISPATCH and FIRST_RESPONDER include context info card
  (CAD_UNIT_SELECT_VALUE + CAD_EVENT_SELECT_VALUE) prepended to each entity form.

BADGENUMBER / dexStateUserId (v1.1 -- auto-populated):
  Badge is auto-populated from officer RMS profile via dexStateUserId.
  Form: hidden InpH 'dexStateUserId' on all 5 QIF forms (hidden row per form).
  QIDM: BadgeNumber attribute sourceField = @('dexStateUserId') on all badge QIDMs.
  Combinations: all set[]/any[] refs use 'dexStateUserId' (not 'BadgeNumber').
  AUTH config: CommsysGetDexStateUserIdRuleHandler already present -- no change needed.

  Paths where dexStateUserId is in set[] (always fires if these other fields are present):
    ACVR/ACVRV: dexStateUserId + LicensePlateNumber / VehicleIdentificationNumber
    ACQG:       dexStateUserId + GunSerialNumber
    ACQA:       dexStateUserId + ArticleTypeCode + ArticleSerialNumber
    ACQB/ACQBH: dexStateUserId + RegistrationNumber / BoatHullIdNumber
    ACWL:       dexStateUserId + BirthDate + NameLast + NameFirst + SexCode
  Paths where dexStateUserId is in any[] (fires if present, but not required):
    DQ, DQN, DQSS, BQ, BQH, ACQW, ACQWN, ACQM, ACQMN

  Note: because dexStateUserId is always auto-populated, ACQB now always sees badge present.
  Combination routing for ACQB vs BQ therefore depends on RegistrationNumber being filled.
  Confirm during test BOA-1 (ACQB) vs BOA-3 (BQ).

WANTED/MISSING:
  WMPIWantedPersonInquiry: ACQW (Name+DOB+Sex+Race) + ACQWN (NCICNumber)
  WMPIMissingPersonInquiry: ACQM (Name+descriptors) + ACQMN (NCICNumber)
  Both targetEntity='Person'. Discriminating fields prevent cross-firing:
    Wanted: BirthDate+SexCode+RaceCode distinguishes from Missing (Age+Height+Weight+Eye+Hair)
