2. DriverLicenseQuery -- Person Entity (DL)
================================================================================
  v3.5 SCOPE CORRECTION: was AzAzdpsDriverLicenseQuery, an out-of-Basic transaction. AZ's metadata
  defines BOTH it and the unprefixed DriverLicenseQuery as SEPARATE transactions with DIFFERENT
  <Requirements>; only the unprefixed one is in the devdoc "Basic Queries Supported" list. Switching
  ADDED the two driver-photo paths (DQPN/DQP, metadata DQP, devdoc #2/#5 -- DQP exists ONLY under the
  Basic transaction, so AZ previously had NO photo request at all), LOOSENED the name search to
  Set[Name] (devdoc #3 -- previously DOB and sex were both mandatory), and DELETED DQSS, an SSN
  search the Basic devdoc does not list. 5 combos, 8 devdoc combinations covered.

  QIDM: AZ_AZDPS_DriverLicenseQuery
  QIF:  ENTITY_Person
  queryLabel: Driver License
  Combos: DQPN (Photo+Name), DQP (Photo+OLN), ACWL (Badge+Name), DQN (Name), DQ (OLN)
  autoSelect: true (co-fires with DH)
  ORDER IS LOAD-BEARING: DQ{OLN} set[] is a STRICT SUBSET of DQP{OLN} set[], so DQP must precede DQ
  or the photo path is dead on arrival; DQN set[] is a subset of both ACWL and DQPN.

  DQPN -- Photo request by Name (devdoc #2) [CONFIRMED]
    set: dexStateUserId, ImageIndicator, NameLast, NameFirst, Requestor
    any: BirthDate, SexCode, nameMiddle, nameSuffix
    conditions: OperatorLicenseNumber NOT_EXISTS   (OLN>Name guardrail)
    keyReference: DQPN (invented -- metadata keyRef DQP carries two variants)
    metadata: DQP{Name} = Set[BadgeNumber, ImageIndicator, Name, Requestor] Any[BirthDate, SexCode]
    NOTE: NO State -- that variant defines none, so RegistrationState is deliberately absent from any[]

  DQP -- Photo request by OLN (devdoc #5) [CONFIRMED]
    set: dexStateUserId, ImageIndicator, OperatorLicenseNumber, Requestor
    any: (none -- metadata defines NO <Any> for this variant)
    keyReference: DQP
    metadata: DQP{OperatorLicenseNumber} = Set[BadgeNumber, ImageIndicator, OperatorLicenseNumber, Requestor]

  ACWL -- Badge + Name + DOB + Sex (devdoc #1 In / #6 Out) [CONFIRMED]
    set: dexStateUserId, BirthDate, NameLast, NameFirst, SexCode
    any: nameMiddle, nameSuffix, RegistrationState
    conditions: dexStateUserId EXISTS; OperatorLicenseNumber NOT_EXISTS
    keyReference: ACWL
    metadata: ACWL{Name} = Set[BadgeNumber, Name, SexCode, BirthDate] Any[OperatorLicenseNumber, State]
    NOTE: metadata's Any[OperatorLicenseNumber] deliberately NOT carried -- OLN is this combo's
          NOT_EXISTS gate, and gate-xor-companion (verify_build CHECK 14) forbids both roles.

  DQN -- Name (devdoc #3 In / #7 Out) [CONFIRMED]
    set: NameLast, NameFirst
    any: BirthDate, SexCode, dexStateUserId, nameMiddle, nameSuffix, RegistrationState
    conditions: OperatorLicenseNumber NOT_EXISTS
    keyReference: DQN (invented -- metadata keyRef DQ carries two variants)
    metadata: DQ{Name} = Set[Name] Any[BirthDate, SexCode, State]  -- NAME ALONE IS SUFFICIENT
    Name: FormatStringRuleHandler "Last, First Middle Suffix"
    BirthDate: CommsysParseDateRuleHandler yyyy-MM-dd -> yyyyMMdd
    Sex: NIBRS reverse-lookup -> M/F/U

  DQ -- OLN (devdoc #4 In / #8 Out) [CONFIRMED]
    set: OperatorLicenseNumber
    any: RegistrationState
    keyReference: DQ
    metadata: DQ{OperatorLicenseNumber} = Set[OperatorLicenseNumber] Any[State]
    NOTE: v3.5 stripped BirthDate, SexCode and dexStateUserId from any[] -- this variant defines
          none of them, so carrying them OVER-PERMITTED on every OLN query.
    keyReference: ACWL
    Notes: MVD/ACIC badge-required path.

  OOS -- OLN with non-AZ state [PENDING]
  Priority -- OLN+Name both filled: DQ fires (OLN wins) [PENDING]
  RMS co-fire: RMS Person combo fires alongside CommSys [PENDING]
