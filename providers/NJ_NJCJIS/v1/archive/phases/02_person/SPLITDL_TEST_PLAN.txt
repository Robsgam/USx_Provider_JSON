LIMITATION #2 SPLIT DL TEST
============================
File   : NJ_NJCJIS_splitDL_test.json
Built  : 2026-04-08
Purpose: Determine whether the platform auto-switches between two separate
         QUERYINPUTDATAMAPPING configs for the same query and entity.

================================================================================
BACKGROUND
================================================================================

LIMITATION #2 was inferred, not directly tested. In v1.7, DriverLicenseQuery
was split into _OLN and _Name configs. The Name path returned "configuration
input requirements have not been met." We concluded the OLN config was staying
active and blocking the Name config. We fixed it by merging in v2.1.

However we never ran a controlled test. The failure may have been:
  (a) Cold-start: Name config never activated even fresh
  (b) Warm-switch: OLN config stayed active after being used; Name never tried
  (c) Something else entirely (wrong combination definition, ordering, etc.)

If (b) but not (a): split configs work on first use but not after switching.
If neither (a) nor (b): original error had a different cause; split configs viable.
If LIMITATION #2 is not real, split configs give true field isolation:
  OLN config attributes = [OLN, State, Image] only -- Name/DOB never sent
  Name config attributes = [Name, DOB, Sex, State, Image] only -- OLN never sent

================================================================================
WHAT THIS BUILD DOES
================================================================================

NJ_NJCJIS_splitDL_test.json has 9 configs in the NJ_NJCJIS bundle:
  NJ_NJCJIS_DriverLicenseQuery_OLN  -- DQN combination only
    attributes: OperatorLicenseNumber, State, Image
  NJ_NJCJIS_DriverLicenseQuery_Name -- DQ combination only
    attributes: BirthDate, Name (First+Last), SexCode, State, Image

Both configs: autoSelect=true, same query/entity (DriverLicenseQuery/Person).
Person form is unchanged -- all fields still visible on the same card.
