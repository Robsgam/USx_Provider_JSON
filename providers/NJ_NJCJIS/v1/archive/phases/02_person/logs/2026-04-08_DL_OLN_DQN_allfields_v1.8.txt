ANALYSIS
================================================================================

  PASS -- OLN path (DQN) fired correctly.
    Only OLN and State sent. Name/DOB/SexCode excluded.
    Attribute-list split between DriverLicenseQuery_OLN and DriverLicenseQuery_Name
    continues to work as intended.

  ISSUE -- ImageIndicator still not sent despite size=1 fix in v1.8.
    v1.8 added size=1 to the Image attribute in both DL configs.
    Result is unchanged from v1.7: ImageIndicator absent from outgoing request.

  ROOT CAUSE IDENTIFIED -- ImageIndicator FormSelect has no initialValue.
    HIDLE.json RelatedSearchHitIndicator (the confirmed working YES_NO_UNKNOWN
    field) has initialValue: "Y" set on the FormSelect node. Our ImageIndicator_Input
    has no initialValue -- the field starts blank/unselected.
    Platform does not send blank/unselected FormSelect fields regardless of size.
    The size fix was necessary but not sufficient -- size controls serialization of
    a non-empty value; initialValue ensures the field is never blank.

  FIX -- Add initialValue: "Y" to ImageIndicator_Input FormSelect.
    This matches the HIDLE pattern for YES_NO_UNKNOWN fields.
    After fix: ImageIndicator will default to "Y" and always be included in
    the request unless the user clears it. User can change to "N" (or "U" --
    YES_NO_UNKNOWN exposes all three values; U cannot be suppressed at the
    FormSelect level without switching to FormInput).

  PENDING -- Confirm YES_NO_UNKNOWN dropdown is showing Y/N/U options.
    codeTypeCategory=YES_NO_UNKNOWN, codeTypeSource=NIBRS matches HIDLE pattern
    exactly and should be correct. With initialValue="Y", the field will be
    pre-populated and visible even if the dropdown options haven't been confirmed.
