================================================================================
SHARED LIMITATIONS (both providers hit these)
================================================================================

1. DUAL-VALUE FIELD PROBLEM  <-- most impactful shared issue
   When one form field must serve two consumers expecting different formats,
   there is no mapping-level conversion available.
   The only fix is dual hidden fields.
     NJ: State field -- SelH (attributeTypeId=STATE) for RMS
                        InpH (initialValue=NJ) for outbound XML
                        STATUS: RESOLVED
     FL: SexCode    -- attributeTypeId=SEX for RMS
                        codeTypeSource=NIBRS/codeTypeCategory=NIBRS_SEX for outbound XML
                        STATUS: UNRESOLVED -- awaiting Option A vs B decision

2. No conditional field visibility
   hidden is static only (true/false).
   Cannot show/hide fields based on user input.
   Workaround: single card with all fields visible; QIDM combinations handle routing.

3. No field styling
   No font size, color, weight, or emphasis on any node type.
   Workaround: field ordering and card titles only.

4. No standalone text/label component
   Available components: Card, Row, FormInput, FormSelect, FormDate, FormCheckbox.
   Workaround: Card.props.title for instructional text (plain text only).

5. Card title renders plain text only -- no HTML
   Workaround: ALL CAPS for emphasis.

6. Article Type requires codeTypeSource = CA_CLETS
   NCIC_ARTICLE_TYPE lives under CA_CLETS. Using NCIC gives an empty dropdown.

7. GunMake is free-text FormInput
   No confirmed codeTypeSource/codeTypeCategory for firearm make on either provider.

8. QUERYINPUTFORM must be in ENTITIES bundle only
   Adding it to the RMS bundle duplicates all entity forms in the UI.

9. QUERYRESULTDATAMAPPING unvalidated (both)
   Both inherited from HI_HCJDC. Neither has been tested against live responses.

10. FIRST_RESPONDER layout key unconfirmed (both)
    Platform recognition not verified on either project.

11. YES_NO_UNKNOWN required -- not YES_NO
    YES_NO gives an empty dropdown. YES_NO_UNKNOWN (NIBRS) is the working option.
    Note: includes U (Unknown) which cannot be suppressed at the FormSelect level.

NJ_NJCJIS -- INDIVIDUAL LIMITATIONS
================================================================================

- attributeTypeId=STATE dual-value: RESOLVED
    SelH 'RegistrationState' (attributeTypeId=STATE) -- feeds RMS, NOT in QIDM
    InpH 'RegistrationStateNJ' (initialValue=NJ) -- in QIDM, sends literal NJ
    Reference: docs/CONNECTCIC_STATE_FIELD_RMS_FIX.txt

- LicensePlateNumberIn / LicensePlateNumberOut required for RMS plate search
    Generic fieldId 'LicensePlateNumber' does NOT trigger RMS plate search.
    LicensePlateNumberIn  = NJ in-state forms
    LicensePlateNumberOut = OOS forms
    QIDM targetField remains 'LicensePlateNumber' (outbound XML unchanged).

- Query summary shows attribute ID for hidden SelH state field
    Platform summary widget keys on attributeTypeId fields regardless of
    field order, bundle order, or hidden status. Cannot be fixed from JSON side.
    Cosmetic only. No functional impact.
    Requires CommSys vendor support (platform aliasing or RMS 2-letter code support).

- VehicleStolenQuery missing from server-side NJ_NJCJIS.xml
    Cannot build QIDM until CommSys registers the transaction server-side.

- QIDM keyReference must be unique per mapping
    NJ combos suffixed _NJ to avoid collision with OOS combos sharing same QIDM.
    (RQ_NJ, RQN_NJ, DQN_NJ vs RQ, RQN, DQN, DQ, BQ, BQN)

================================================================================
FL_FCIC -- INDIVIDUAL LIMITATIONS
================================================================================

- attributeTypeId=SEX dual-value: UNRESOLVED
    Same root cause as NJ state issue. Two consumers need incompatible formats.
    Option A: Remove SexCode from RMS requirements.any (RMS loses sex filter)
    Option B: Dual hidden fields -- SexCode (NIBRS code value) + SexCodeRMS (attr ID)
    NJ dual-field pattern applies directly to Option B.
    Current state: FL FCIC working, RMS sex filtering broken.

- OOS VIN RMS 400 bad request error
    ENTITY_Vehicle_OOS RegistrationState uses attributeTypeId=STATE.
    Likely sends attribute ID to RMS on VIN path -- same class as NJ RMS fatal.
    Pending investigation. NJ dual-field state fix may apply here as well.

- FL uses non-standard transaction keys
    FRQ (FL vehicle), FDQ (FL DL), FBQ (FL boat), KQ (FL driver history)
    These are FCIC/DHSMV-specific. No cross-provider reuse.

- DriverHistoryQuery (KQ) is FL-specific
    No NJ equivalent. Requires PurposeCode and Attention fields.
    KQ key acceptance by platform not yet confirmed.

- Multiple routing keys per query type
    VehicleRegistrationQuery: FRQ (FL) + QV (NCIC stolen) + RQ (Nlets OOS)
    BoatQuery: FBQ (FL) + QB (NCIC stolen)
    DriverLicenseQuery: FDQ (FL) + QW (FCIC) + DQ (Nlets OOS)
    Each routes to a different system. All handled in one QIDM per query type.

- autoSelect / queriesToDeselect required for DL/DH deconfliction
    DriverLicense and DriverHistory share the Person form.
    Without autoSelect/queriesToDeselect, both queries fire simultaneously.
    Audit of non-DL/DH mappings for these fields is incomplete.

- 3 layout variants required: default, CAD_DISPATCH, FIRST_RESPONDER
    NJ uses only default. FL requires all three per entity form.
    All 34 changes applied to all 3 variants per entity.

- PurposeCode code list TBD
    Valid KQ values: A, C, D, E, F, H, J, O, R.
    Currently FormInput free-text. No confirmed platform code list.
