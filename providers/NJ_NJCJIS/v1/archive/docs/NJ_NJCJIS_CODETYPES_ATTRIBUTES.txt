================================================================================
STATE FIELD ARCHITECTURE (NJ_NJCJIS-specific)
================================================================================

  NJ in-state forms (Vehicle NJ, Person NJ):
    Field 1: SelH  fieldId='RegistrationState'    attributeTypeId='STATE'  initialValue='NJ'
             -- Hidden. Sends internal attribute ID (69509884952) to RMS elastic search.
             -- NOT in QIDM. Never reaches outbound XML.
    Field 2: InpH  fieldId='RegistrationStateNJ'  initialValue='NJ'
             -- Hidden. QIDM sourceField for StateNJ attribute. Sends 'NJ' to outbound XML.

  OOS forms (Vehicle OOS, Person OOS):
    Field:   Sel   fieldId='RegistrationStateOOS'  codeTypeCategory='NJ_NIBRS_STATE'
                   codeTypeSource='NJ_NIBRS'
             -- Visible dropdown. Sends 2-letter state code to outbound XML.
             -- No attributeTypeId -- does not interact with RMS attribute lookup.

  Boat form:
    Field:   Sel   fieldId='RegistrationStateOOS'  codeTypeCategory='NJ_NIBRS_STATE'
                   codeTypeSource='NJ_NIBRS'  initialValue='NJ'
             -- Visible dropdown, defaults to NJ. Changed by operator for OOS boat queries.

  Why this matters (for comparison):
    attributeTypeId='STATE' on any FormSelect causes the platform to send the
    internal numeric attribute ID (e.g., 69509884952) instead of the 2-letter code.
    This is correct for RMS elastic search but wrong for outbound XML.
    codeTypeCategory='NJ_NIBRS_STATE' sends the 2-letter code -- safe for outbound XML
    and does not cause RMS fatal errors.

================================================================================
PLATFORM BEHAVIOR NOTES (for comparisons with other JSONs)
================================================================================

  1. NJ_NIBRS_STATE is an NJ-specific code list -- other providers will use a different
     codeTypeCategory/codeTypeSource for state dropdowns (or attributeTypeId='STATE').

  2. attributeTypeId='STATE' always sends an internal numeric ID, not a 2-letter code.
     Only use on hidden fields for RMS; never map in QIDM for outbound XML.

  3. YES_NO_UNKNOWN / NIBRS is the platform's standard boolean dropdown.
     Shared across providers -- safe to compare directly.

  4. NCIC_LICENSE_PLATE_TYPE / NCIC and VEHICLE_BODY_STYLE / NCIC are standard NCIC
     code lists -- should be the same across any NCIC-sourced provider JSON.

  5. CA_CLETS codeTypeSource on ArticleTypeCode: inherited from HIDLE base;
     may not be correct for NJ -- flag for CommSys vendor review.

  6. LicensePlateNumberIn and LicensePlateNumberOut are NJ_NJCJIS-specific fieldIds.
     Other providers may use generic LicensePlateNumber if they do not need RMS plate
     search differentiation.
