NJ_NJCJIS / ConnectCIC Platform Limitations
============================================
Last updated: 2026-04-10
Newest discoveries at top.

================================================================================
SEX FIELD / RMS ELASTIC SEARCH
================================================================================

21. useAttributeId=True in RMS QIDM does NOT convert code values to attribute IDs  (confirmed v3.20, tested 2026-04-10)
    - NIBRS_SEX codeTypeCategory sends "M"/"F"/"U" codes (correct for CommSys XML).
    - RMS person QIDM maps SexCode -> sexAttrId with useAttributeId=True.
    - Tested expectation: platform performs "M" -> 69509891711 (numeric attribute ID).
    - Actual result: RMS received sexAttrId:"M" and returned 400 error.
    - useAttributeId=True only works when the form field itself has attributeTypeId set
      (e.g., attributeTypeId='STATE' or attributeTypeId='SEX') -- it passes through the
      already-resolved attribute ID from the field. It does NOT convert code values.
    - SERVER-SIDE LIMITATION: no config mechanism converts codeTypeCategory codes to
      RMS attribute IDs. Sex filtering is available in CommSys XML only.
    - Fix (v3.21): Patch 3 permanently removes sexAttrId/sexAttrIds/useAttributeId from
      all RMS person QIDM combinations. Sex field (NIBRS_SEX) remains on the form and
      sends correctly to CommSys outbound XML.

================================================================================
STATE FIELD / RMS ELASTIC SEARCH
================================================================================

13. attributeTypeId='STATE' on FormSelect sends internal numeric attribute ID  (found v3.x)
    - Any FormSelect (visible or hidden) with attributeTypeId='STATE' sends the platform's
      internal attribute ID for the selected value rather than the 2-letter state code.
      Example: NJ → 69509884952, PA → 69509887513.
    - This is correct for RMS elastic search (which expects the attribute ID).
    - This is wrong for outbound XML to NJ NJCJIS (which expects 'NJ', 'PA', etc.).
    - Do NOT map a field with attributeTypeId='STATE' in QIDM -- it will send the ID
      in the outbound XML and the provider will reject or misinterpret the query.

14. RMS elastic search fatals on VIN/OLN queries when state is plain text  (found v3.11)
    - RMS elastic search recognizes fieldId='RegistrationState' and expects an internal
      attribute ID value. When the value is plain text (e.g., 'NJ'), RMS throws a
      fatal local error and the query does not complete.
    - Plate-only queries do not trigger RMS state validation -- only VIN and OLN paths.
    - Fix: dual-field approach (see limitation 15).
    - Dead end documented: IgnoreUserValueRuleHandler (limitation 17).

15. Dual-field state pattern required for NJ in-state forms  (resolved v3.12)
    - Two hidden fields serve different consumers:
        Field 1: SelH  fieldId='RegistrationState'   attributeTypeId='STATE'  initialValue='NJ'
                 → RMS elastic search reads this field by fieldId; receives attribute ID.
                 → NOT in QIDM. Never reaches outbound XML.
        Field 2: InpH  fieldId='RegistrationStateNJ'  initialValue='NJ'
                 → QIDM sourceField; sends literal 'NJ' to outbound XML <State> element.
    - OOS forms use codeTypeCategory='NJ_NIBRS_STATE' which sends the correct 2-letter code
      to outbound XML and avoids RMS fatal errors. However, OOS RMS searches fire without
      state filtering -- see SERVER-SIDE LIMITATION below.
    - Reference: docs/CONNECTCIC_STATE_FIELD_RMS_FIX.txt, docs/OOS_STATE_RMS_ANALYSIS.txt

20. OOS RMS plate/VIN searches fire without state filter  (confirmed v3.16, tested 2026-04-10)
    - codeTypeCategory fields send 2-letter codes; RMS elastic requires attribute IDs.
    - attributeTypeId=STATE fields send attribute IDs; outbound XML requires 2-letter codes.
    - No config mechanism can serve both consumers from a single user-selected field.
    - SERVER-SIDE LIMITATION: requires a platform-level conversion handler. Not solvable
      in JSON config. Full investigation in docs/OOS_STATE_RMS_ANALYSIS.txt.
    - Current behavior (v3.16): RMS fires with plate/VIN tag only (no state filter).
      Officer confirms state visually. Outbound XML state is always correct.

16. LicensePlateNumberIn / LicensePlateNumberOut required for RMS plate search  (found v3.13)
    - RMS elastic search recognizes specific fieldIds for plate queries.
    - fieldId='LicensePlateNumber' (generic) does NOT trigger RMS plate search.
    - fieldId='LicensePlateNumberIn'  triggers RMS plate search on NJ forms.
    - fieldId='LicensePlateNumberOut' triggers RMS plate search on OOS forms.
    - These fieldIds come from HIDLE.json and must match exactly.
    - QIDM targetField is still 'LicensePlateNumber' (outbound XML element name unchanged).

17. IgnoreUserValueRuleHandler does not override sourceField value  (tested v3.10 -- dead end)
    - Tested to force a hardcoded state value when a populated SelH sourceField was present.
    - Handler passes the raw sourceField value through unchanged when the field is populated.
    - The argument value (e.g., 'NJ') is not substituted.
    - Do not use for state field hardcoding. Use InpH with initialValue instead.

18. Query display summary shows internal attribute ID for hidden state field  (no fix found)
    - The ConnectCIC summary widget surfaces the raw value of any field with attributeTypeId.
    - SelH 'RegistrationState' has attributeTypeId='STATE' so the summary always shows its
      raw value: the internal attribute ID (e.g., 69509884952) instead of 'NJ'.
    - ATTEMPTED FIXES (all failed or not viable):
        v3.14: swapped field order (InpH before SelH) -- no effect; summary still shows ID
        Bundle order change -- no effect; summary reads raw form values, not bundle output
        IgnoreUserValueRuleHandler -- confirmed dead end (v3.10, LIMITATION #17)
        Remove SelH from form -- breaks RMS elastic search (requires attributeTypeId=STATE)
    - ROOT CAUSE: RMS elastic search requires fieldId='RegistrationState' with the internal
      attribute ID. The SelH must stay in the form. The summary widget will always pick it up.
    - STATUS: SERVER-SIDE LIMITATION. No config fix available. Both server-side options
        would require platform changes outside JSON config scope:
        a) Summary aliasing -- server displays a designated field instead of the attributeTypeId field
        b) RMS accepts 2-letter state codes so the SelH can be removed entirely
    - Functional impact: NONE. Outbound XML sends correct <State>NJ</State>. RMS searches correctly.

19. keyReference must be unique within a QUERYINPUTDATAMAPPING  (found v3.12)
    - Import error: "Duplicate key references found in query input data mapping."
    - Each combination within a single QIDM must have a distinct keyReference value.
    - When NJ and OOS combinations share the same QIDM (VehicleRegistrationQuery,
      DriverLicenseQuery), NJ combinations must use distinct names.
    - Resolution: suffix NJ combinations with _NJ (RQ_NJ, RQN_NJ, DQN_NJ).
      OOS combinations retain their original names (RQ, RQN, DQN, DQ, BQ, BQN).

================================================================================
QUERY BEHAVIOR
================================================================================

1. set[] and any[] control combination matching only -- not field sending  (confirmed v2.1)
   - set[] = required fields that must ALL be present for the combination to fire.
   - any[] = optional fields the combination recognizes; used for routing priority only.
   - When a combination fires, ALL populated attributes IN THE CONFIG are sent,
     regardless of whether they appear in set[] or any[].
   - set/any cannot filter or suppress which attributes from the same config are sent.
   - True field isolation requires split configs (see item 2).
   - Practical impact: server confirmed tolerant of extra fields. OLN path (v2.1)
     sent Name/BirthDate/SexCode as extras; queries still returned results.
   - Production workaround (v2.7+): merged single config. Operators typically fill
     OLN OR Name, not both, so extra fields are usually blank and not serialized.

2. Split configs for same query/entity -- DQ combination does not fire in isolation  (found v2.6)
   - CONTROLLED TEST RESULT (2026-04-08, NJ_NJCJIS_splitDL_test.json, 4 tests):
       T1 Cold Name path      result uncertain -- old merged config likely fired (both were active)
       T2 Cold OLN path       PASS
       T3 Warm OLN->Name      result uncertain -- same caveat as T1
       T4 Warm Name->OLN      PASS
   - v2.6 production test (split configs only, merged config removed):
       OLN path cold          PASS -- split OLN config confirmed working
       Name path cold         FAIL -- DQ combination did not fire; no XML request built
   - Root cause unknown. Hypothesis: platform requires DQN and DQ in the same config,
     or locks onto the first-listed config (OLN) and fails rather than falling through
     to the Name config.
   - See docs/SPLITDL_REFERENCE.txt for full split config source and retry strategy.
   - Production decision: merged config (v2.7+). Revisit with live connection.

3. FormSelect blank/unselected field is not sent  (found v1.9)
   - Platform does not serialize a FormSelect that has no value selected.
   - size on the attribute is irrelevant if the field value is empty.
   - Fix: add initialValue to any FormSelect that should always be pre-populated.
   - HIDLE pattern: YES_NO_UNKNOWN fields use initialValue: "Y".
   - Applied to ImageIndicator_Input in v1.9: initialValue = "Y".
   - A cleared FormSelect (user clicked the platform's clear button) is not sent.
     This is correct optional-field behavior -- clearing means "omit from request."

FORM LAYOUT
================================================================================

4. No conditional field visibility
   - hidden is static only (true/false). Cannot show/hide based on user input.
   - Workaround: single card with all fields visible; QUERYINPUTDATAMAPPING
     combinations handle query routing by what the user populates.

5. No field styling
   - No font size, color, weight, or emphasis props on any node type.
   - Workaround: field ordering and Card titles only.

6. No standalone text/label component
   - Available components: Card, Row, FormInput, FormSelect, FormDate, FormCheckbox.
   - No standalone text or label element exists.
   - Workaround: Card.props.title for instructional text (plain text only).

7. Card title prop renders plain text only -- no HTML
   - HTML tags such as <strong> appear verbatim in the UI.
   - Workaround: use ALL CAPS for emphasis in card titles.

CODE TYPES / DROPDOWNS
================================================================================

8. YES_NO codeTypeCategory is not recognized -- use YES_NO_UNKNOWN  (found v1.7)
   - YES_NO results in an empty dropdown (not a recognized platform code type).
   - YES_NO_UNKNOWN (NIBRS) is confirmed working; shows Y, N, and U as options.
   - U cannot be suppressed at the FormSelect level. If U must be excluded,
     switch to FormInput maxLength=1 (free text).
   - FormSelect also has a platform clear button that blanks the value entirely.

9. Article Type dropdown requires codeTypeSource = CA_CLETS  (found v1.0)
   - NCIC_ARTICLE_TYPE lives under codeTypeSource "CA_CLETS" in this system.
   - Using codeTypeSource "NCIC" results in an empty dropdown.

10. Firearm Make and Caliber -- no platform code list  (found v1.0)
    - No confirmed codeTypeSource/codeTypeCategory for GunMake or GunCaliber in NJ.
    - Resolution: FormInput with maxLength from XML spec. Confirmed correct by FL_FCIC.

================================================================================
MULTI-QUERY PERSON FORMS (from FL_FCIC, confirmed 2026-04-10)
================================================================================

22. autoSelect + queriesToDeselect -- mutual exclusion between two QIDMs on the same form
    (confirmed in FL_FCIC production JSON, 2026-04-10)
    - When two QIDMs can both fire from the same person form (e.g., DL and DH share
      the same Person tab), set autoSelect=true and queriesToDeselect=[other query]
      on each QIDM.
    - Effect: when DH fires, DL is automatically deselected; when DL fires, DH is
      automatically deselected. Prevents double-query submission.
    - FL_FCIC implementation:
        FL_FCIC_DriverHistoryQuery:  autoSelect=true, queriesToDeselect=["DriverLicenseQuery"]
        FL_FCIC_DriverLicenseQuery:  autoSelect=true, queriesToDeselect=["DriverHistoryQuery"]
    - NJ CURRENT STATUS: Not needed yet. NJ has no DriverHistoryQuery. If DH is added
      to the Person NJ or Person OOS tab in a future phase, apply this pattern.

23. DH-specific fieldId suffixes -- mutual exclusion within a merged QIDM
    (confirmed in FL_FCIC production JSON, 2026-04-10)
    - When DL and DH share a person form and are in separate QIDMs, DH combinations
      use suffixed fieldIds (NameFirstDH, NameLastDH, BirthDateDH, SexCodeDH,
      OperatorLicenseNumberDH) in set[].
    - DH form fields use those DH-suffixed fieldIds. DL form fields use the standard
      fieldIds (NameFirst, NameLast, etc.).
    - Because DL combinations require the non-suffixed fields, they cannot accidentally
      fire when the officer only filled DH fields, and vice versa.
    - QIDM attributes map the suffixed sourceFields to standard targetField names in
      the outbound XML (e.g., sourceField=NameFirstDH -> targetField=Name).
    - This approach avoids split configs entirely, sidestepping LIMITATION #2.
    - NJ CURRENT STATUS: Not needed yet. If DH is added to NJ Person forms, use this
      pattern rather than split configs.

24. clearable: true on optional pre-populated FormSelect fields
    (confirmed in FL_FCIC production JSON, 2026-04-10)
    - Adding clearable: true to a FormSelect lets the officer explicitly clear the
      field (removes the value entirely rather than reverting to initialValue).
    - FL_FCIC applies this to LicensePlateYear fields.
    - Useful for any optional field with an initialValue where the officer may want
      to omit it from a search (e.g., PlateYear, VehicleYear).
    - NJ APPLICABILITY: Consider adding to LicensePlateYear on Vehicle NJ/OOS tabs.

ARCHITECTURE
================================================================================

11. Duplicate QUERYINPUTFORM cards if added to both ENTITIES and RMS bundles
    - Adding QUERYINPUTFORM to the RMS bundle causes each entity form to render twice.
    - Resolution: QUERYINPUTFORM belongs only in the ENTITIES bundle (provider=MARK43).

12. VehicleStolenQuery not in NJ_NJCJIS.xml  (flagged v1.6)
    - NJ_NJCJIS.xml defines only 5 transactions: ArticleSingleQuery, BoatQuery,
      DriverLicenseQuery, GunQuery, VehicleRegistrationQuery.
    - SERVER-SIDE LIMITATION: VehicleStolenQuery is not registered in the server-side
      provider XML. A QUERYINPUTDATAMAPPING cannot be built until the server registers
      the transaction. No config-side fix available.
