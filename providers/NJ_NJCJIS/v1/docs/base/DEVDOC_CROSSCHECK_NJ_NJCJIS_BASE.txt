================================================================
  STATE PATTERN NOTE
================================================================

  The PDF devdoc marks State as required (before brackets / M) for:
    - VehicleRegistrationQuery RQ and RQN
    - DriverLicenseQuery DQN

  The XML metadata marks State as Any (optional) for ALL combos.

  The build follows the XML (any[]). This is correct for ConnectCIC
  QIDM construction -- the XML defines what the platform enforces.

  However, the PDF reveals that CommSys EXPECTS State on these
  queries. If State is absent, CommSys may reject the query or
  return unpredictable results.

  Current mitigation: RegistrationState form field has
  initialValue=NJ (attributeTypeId=STATE dropdown). State is
  always populated in normal operation.

  Structural improvement available: Move RegistrationState from
  any[] to set[] on RQ, RQN, and DQN combos. This makes State a
  GATE -- the combo won't fire without it. The MC v2.0.2 variant
  already has this pattern on all combos.

  Risk of any[] (current BASE):
    If operator clears State, combo fires WITHOUT State.
    CommSys receives query with no <State> element.
    CommSys behavior undefined per PDF (State is M/C).

  Benefit of set[] (MC pattern):
    If operator clears State, combo does NOT fire.
    Operator sees validation feedback. No bad query sent.

  Recommendation: Backport set[] pattern from MC to BASE for
  RQ, RQN, and DQN. No change needed for DQ (State is optional
  per both PDF and XML) or BQ/BQN (State is Any in XML, not
  listed in PDF).
