PHASE Q4 FIRST -- THE PREMISE TEST (decisive for this branch)
================================================================================
Uses ANY ordinary plate -- no special records required. The evidence is the
STRUCTURE of the responses, not a stolen hit. RAND mode (RandomRequest=Y) is
documented as stolen-only data, so its response shows exactly what NJCJIS's
stolen-check output looks like; the question is whether the FULL response
carries the same check.

Q4a RAND baseline -- what a stolen-check response looks like            [    ]
    Steps : Random dropdown=Y, any plate (e.g. ABC1234). Submit. Capture the
            COMPLETE RESPONSE XML from server logs.
    Expect: Stolen-only response (per RAND documentation) -- note its
            structure: segment names, NCIC markers, and what a NEGATIVE
            stolen result looks like (e.g. "NO RECORD" block vs nothing).
    PASS  : Response captured; stolen-check response structure documented.

Q4b FULL comparison -- does FULL carry the same check?                  [    ]
    Steps : FULL RELOAD. Random dropdown=N (default), SAME plate. Submit.
            Capture the COMPLETE RESPONSE XML.
    Compare against Q4a:
      - FULL response CONTAINS the Q4a-style stolen-check segment (even as a
        negative/"NO RECORD" block) alongside DMV data -> premise SUPPORTED.
      - FULL response has ONLY registration data, none of the Q4a stolen
        markers -> premise NOT SUPPORTED: this variant loses stolen-check
        capability entirely (no QV query in JSON, no NCIC# path). STOP and
        escalate before further testing.
      - AMBIGUOUS (e.g. Q4a negative produces no visible segment either) ->
        structure comparison cannot decide; escalate the documentation
        question to CommSys/NJCJIS ("does a FULL VehicleRegistrationQuery
        include the NCIC stolen check?") and HOLD this branch. Do NOT plan
        around acquiring special records to force a hit.
    PASS  : Verdict reached (or escalated) with both response XMLs attached.
    NOTE  : If premise supported, also verify the platform DISPLAYS the
            stolen segment of the FULL response (QRDM kept intact for this).
