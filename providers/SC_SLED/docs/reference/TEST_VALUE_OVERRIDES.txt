# TEST_VALUE_OVERRIDES -- SC_SLED
#
# Synthetic fill values for fields the shared resolver has no default for. Format: fieldId=value,
# '#' comments, read by tools\_combo_value_resolver.ps1 (Get-ComboValueOverrides) for both
# emit_test_plan.ps1 and generate_test_matrix.ps1.
#
# WHY THIS FILE EXISTS. Rob 2026-09-16: "make sure we have all the combos represented in the test
# skill." Measured answer at v1.5: 15 of 18 built combinations had a plan test and THREE did not.
# One cause was here -- a mandatory field with NO test value produces NO test at all, so the
# combination silently disappears from the plan and `audit_test_coverage` reports it as 0 logs
# forever. The provider can then never reach ALL-PASS, and nothing in the plan says why.
# emit_test_plan DOES print the reason by name ("'OriginatingAgencyCaseNumber' has no test value
# (unmapped in Get-TestValue)") -- it was simply an orphaned finding nobody consumed, the same
# shape CLAUDE.md records for the PHASE 2 fillability check.
#
# ⚠️ THE FIX IS TEST DATA, NOT A BUILD CHANGE. Do not "fix" an unmapped field by editing the JSON.
#
# --- QWA.OCA : WantedPerson by name + originating agency case number ---------------------------
# Without this the fill degraded to Name only, matched QWA.N instead (which is legal -- QWA.N is
# set[NameLast,NameFirst]), and emit_test_plan dropped QWA.OCA as "its fill fires QWA.N instead".
# That reason was TRUE of the incomplete fill and FALSE of the combination: QWA.OCA is ordered
# BEFORE QWA.N and is strictly more specific, so a complete fill reaches it.
# Devdoc size 20, free text.
OriginatingAgencyCaseNumber=SC2026001234
#
# --- QWA.P : WantedPerson by wanted-vehicle plate --------------------------------------------
# set[LicensePlateNumber, LicensePlateStateCode]. The state code is MANDATORY in that pair, and at
# v1.3 it became a TYPE-IN rather than a dropdown (LIMITATION #28 -- see the build script), so a
# synthetic value is needed here rather than a picklist selection.
# 'SC' is the in-state code and keeps the test on the provider's own state.
LicensePlateStateCode=SC
#
# --- AM : AdministrativeMessage ----------------------------------------------------------------
# set[FreeText]. The devdoc caps it at 501 characters; a short readable string is enough to prove
# the tag transmits, and a 501-char filler would make the captured log unreadable for no gain.
FreeText=USX TEST MESSAGE - PLEASE DISREGARD
#
# --- AM : DestinationCode / DestinationCode2..5 -- DELIBERATELY NOT MAPPED, NEEDS ROB'S CALL ------
# emit_test_plan WARNs 5x: "Article AM any[]: 'DestinationCodeN' has no test value". That WARN is
# CORRECT SIGNAL and is being LEFT IN PLACE rather than silenced with a guess.
#
# WHY. Every other override in this file is a synthetic string that goes into a SEARCH. An
# AdministrativeMessage is not a search -- it DELIVERS free text to the ORI(s) named in these
# fields, into a queue a human at that agency reads. So inventing a 9-character ORI-shaped value
# does not make a test value; it picks a recipient. Guess wrong and we have sent an unsolicited
# message to a real South Carolina agency under the tenant's ORI, which no gate can undo.
#
# The SELF-ADDRESSED option (send it to the originating agency, so the message lands back in our
# own queue) is the obviously safe one, and it cannot be written here: `Build-Auth` takes the ORI
# from the TENANT at runtime, so the build does not know the string. It would have to be read off
# usx-sc-sled after the import and pasted in.
#
# CONSEQUENCE, stated rather than hidden: the AM combination has a plan test for set[FreeText] and
# will be driven, but its five any[] optionals will NOT be, so nothing proves those tags transmit.
# That is a real coverage hole in the AM entity and it is the only one in this provider.
#
# TO CLOSE IT: read usx-sc-sled's own ORI from the tenant after the v1.7 import, then uncomment and
# fill the line below. Do NOT populate 2..5 unless multi-destination broadcast is wanted -- the
# standing 2026-08-02 decision excludes multi-state broadcast (State2..State5) for the same reason.
# DestinationCode=<usx-sc-sled's own ORI, 9 chars>
#
