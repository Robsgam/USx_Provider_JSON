CONNECTCIC RULE HANDLERS -- Complete Reference
===================================================
Last updated: 2026-05-08
Source: All built provider JSONs + _build_rms_bundle.ps1
        + Engineering doc (Crinnger Fagundes de Oliveira, 2026-05-08)

24 unique handlers across the ConnectCIC provider JSON ecosystem.
Found at 4 property paths in the JSON structure.

================================================================================
  CONFIGURATION MODEL -- Attribute Object
================================================================================

  Every mapped field is an Attribute object. The `rule` property defines which
  handler processes the value. Full attribute structure:

  {
    "name":           "AttrName",           // identifier; some handlers use this
    "rule": {
      "function":     "HandlerClassName",   // primary handler
      "arguments":    ["arg1", "arg2"]      // handler-specific arguments
    },
    "fallbackRule": {
      "function":     "FallbackHandler",    // executed when primary value absent
      "arguments":    ["..."]
    },
    "sourceField":    ["key1", "key2"],     // keys in userArguments map
    "targetField":    "TargetField",        // destination field in output
    "attributeType":  "STATE",              // used by CommsysResultAttributeMappingRuleHandler
    "codeTypeSource": "NCIC"               // used by CommsysResultAttributeMappingRuleHandler
  }

  fallbackRule: Triggered automatically by the framework when the primary
  attribute value is absent. Common pattern: primary rule does code lookup,
  fallbackRule uses regex to extract from free text.

================================================================================
  PROPERTY PATHS
================================================================================

  1. handlerFunction       Top-level on configuration objects
                           e.g. bundles[].configurations[].handlerFunction
                           Used on: AUTHENTICATION, QIDM, QMF, QRDM, QUERYRESULTSLAYOUT

  2. rule.function         Inside attribute definitions (primary rule)
                           e.g. bundles[].configurations[].attributes[].rule.function
                           Used on: AUTHENTICATION, QIDM, QRDM attrs

  3. fallbackRule.function Inside attribute definitions (fallback rule)
                           e.g. bundles[].configurations[].attributes[].fallbackRule.function
                           Used on: QRDM attrs (regex fallback parsing)

  4. ParallelQuery.function Top-level on bundle (not configuration)
                           e.g. bundles[].ParallelQuery.function
                           Used on: RMS bundle only

================================================================================
  HANDLER FUNCTIONS (9) -- handlerFunction on configs
================================================================================

  These are top-level handlers that control how entire configs process data.
  Build scripts set these when creating QIDM/Auth/QMF/QRDM configs.

  1. CommsysOriAuthenticationHandler
     Config type:  AUTHENTICATION
     Bundle:       Auth (provider-named, e.g. HI_HCJDC, NJ_NJCJIS)
     Purpose:      ORI-based authentication for CommSys queries
     Source:       _build_provider_helpers.ps1 (Build-Auth)
     All builds:   YES -- every provider has this

  2. RestAuthenticationHandler
     Config type:  AUTHENTICATION
     Bundle:       RMS
     Purpose:      REST API authentication for RMS queries
     Source:       _build_rms_bundle.ps1 (Build-RmsBundle)
     All builds:   YES -- standard RMS component

  3. CommsysTransactionRequestHandler
     Config type:  QUERYINPUTDATAMAPPING (QIDM)
     Bundle:       Provider (e.g. NJ_NJCJIS, NY_NYSPIN_EJUSTICE)
     Purpose:      Builds CommSys XML transaction request from form fields
     Source:       Build script creates each QIDM with this handler
     All builds:   YES -- one per QIDM (6-11 per provider)

  4. CommsysWsiOutgoingMessageHandler
     Config type:  QUERYMESSAGEFORMAT (QMF)
     Bundle:       Provider
     Purpose:      Formats WSI outgoing message envelope for CommSys
     Source:       _build_provider_helpers.ps1 (Build-Qmf)
     All builds:   YES -- exactly one per provider

  5. CommsysResultsHandler
     Config type:  QUERYRESULTDATAMAPPING (QRDM)
     Bundle:       Provider
     Purpose:      Parses CommSys result set into field values
     Source:       _build_provider_helpers.ps1 (Build-ProviderQrdm)
     All builds:   YES -- exactly one per provider

  6. RmsRestPayloadHandler
     Config type:  QUERYINPUTDATAMAPPING (QIDM)
     Bundle:       RMS
     Purpose:      Builds JSON/REST payload for RMS search queries
     Source:       _build_rms_bundle.ps1 (Build-RmsBundle)
     All builds:   YES -- one per RMS QIDM (Person + Vehicle)

  7. RmsRestResultsHandler
     Config type:  QUERYRESULTDATAMAPPING (QRDM)
     Bundle:       RMS
     Purpose:      Parses JSON response from RMS REST API
     Source:       _build_rms_bundle.ps1 (Build-RmsBundle)
     All builds:   YES -- exactly one

  8. RestRequestHandler
     Config type:  QUERYMESSAGEFORMAT (QMF)
     Bundle:       RMS
     Purpose:      Builds HTTP request for RMS REST queries
     Source:       _build_rms_bundle.ps1 (Build-RmsBundle)
     All builds:   YES -- exactly one

  9. QueryResultsLayoutHandler
     Config type:  QUERYRESULTSLAYOUT
     Bundle:       RMS
     Purpose:      Controls result display layout in UI
     Source:       _build_rms_bundle.ps1 (Build-RmsBundle)

================================================================================
  RULE HANDLERS -- QIDM (outbound query building)
================================================================================

  These are attribute-level handlers configured on QIDM attributes in build
  scripts. They transform form field values into CommSys XML element values.

  --------------------------------------------------------------------------
  10. CommsysGetDexStateUserIdRuleHandler
  --------------------------------------------------------------------------
      Config type:  AUTHENTICATION attribute (UserName)
      Arguments:    ['true'] = required, ['false'] = optional
      Purpose:      Retrieves DEX State user ID from logged-in user profile
      Source:       _build_provider_helpers.ps1 (Build-Auth)
      All builds:   YES

      Resolution logic:
        1. Check if userArguments already has DEX_STATE_USER_ID_DEFAULT
        2. If not, fetch via UserProfileService
        3. If isRequired=true and ID absent -> MissingRequiredInputException
        4. Validates DEX certification expiration date -> exception if expired

      Config:
        {
          "name": "UserName",
          "rule": { "function": "CommsysGetDexStateUserIdRuleHandler",
                    "arguments": ["true"] },
          "sourceField": ["dexStateUserId"],
          "targetField": "UserName"
        }

  --------------------------------------------------------------------------
  11. CommsysParseDateRuleHandler
  --------------------------------------------------------------------------
      Config type:  QIDM attribute (BirthDate)
      Arguments:    ['<input-format>', '<output-format>']
                    args[0] = input format (Java DateTimeFormatter pattern)
                    args[1] = output format
      Purpose:      Converts date string from one format to another
      Source:       Build script (on BirthDate attrs in DL/DH QIDMs)
      All builds:   YES (any provider with Person DL/DH queries)

      Returns null if the date cannot be parsed.

      Provider formats:
        NJ:  ['yyyy-MM-dd', 'MMddyyyy']
        CA:  ['yyyy-MM-dd', 'yyyyMMdd']
        Check devdoc for each provider's expected format.

      Config:
        {
          "name": "BirthDate",
          "rule": { "function": "CommsysParseDateRuleHandler",
                    "arguments": ["yyyy-MM-dd", "MMddyyyy"] },
          "sourceField": ["birthDate"],
          "targetField": "BirthDate"
        }

  --------------------------------------------------------------------------
  12. FormatStringRuleHandler
  --------------------------------------------------------------------------
      Config type:  QIDM attribute (Name), also QRDM
      Arguments:    list of separator strings
                    count MUST equal sourceField count minus 1 (AP #15)
      Purpose:      Concatenates multiple sourceFields with separators
      Source:       Build script (on Name attrs)
      All builds:   YES (any provider with Name queries)

      Behavior:
        - Iterates over sourceField in order
        - Fetches each value from userArguments
        - Empty/null fields are SKIPPED
        - Separators are inserted between FOUND values only

      Example: sourceField=["LastName","FirstName"], arguments=[", "]
        Input:  { "LastName": "DOE", "FirstName": "JOHN" }
        Output: "DOE, JOHN"

      3-field example: sourceField=["Street","City","Zip"], arguments=[", "," - "]
        Input:  { "Street": "123 Main", "City": "Springfield", "Zip": "12345" }
        Output: "123 Main, Springfield - 12345"

      Config:
        {
          "name": "Name",
          "rule": { "function": "FormatStringRuleHandler",
                    "arguments": [", "] },
          "sourceField": ["nameLast", "nameFirst"],
          "targetField": "Name"
        }

  --------------------------------------------------------------------------
  13. CommsysGetLastNameFirstNameInitialRuleHandler
  --------------------------------------------------------------------------
      Config type:  QIDM attribute (Attention / RequestingOfficer)
      Arguments:    none (ignores userArguments and attribute)
      Purpose:      Formats logged-in user's name as "LastName FirstInitial"
      Source:       CA_ESUN template, LA_LEMS
      All builds:   NO -- CA_ESUN/LA_LEMS Attention pattern only

      Output format:
        lastName="Smith", firstName="John"  -> "Smith J"
        lastName="Doe",   firstName=""      -> "Doe"
        Invalid profile                     -> null

      Config:
        {
          "name": "Attention",
          "rule": { "function": "CommsysGetLastNameFirstNameInitialRuleHandler" },
          "sourceField": ["Attention"],
          "targetField": "Attention"
        }

      *** CORRECTION 2026-06-22 (live-proven, supersedes earlier "sourceField: []") ***
      sourceField MUST be NON-EMPTY. ConnectCic REJECTS an empty sourceField at
      import: "Invalid Bundle configurations: [Invalid attributes found in query
      input data mapping: [Attention]]" (HI_HCJDC_OFML v2.5 import, 2026-06-22).
      Use sourceField=["Attention"]. The earlier "[]" guidance here was never
      live-validated (CA_ESUN/LA_LEMS do not actually carry this handler) and is
      WRONG for this platform.

      KNOWN LIMITATION (unresolved): with sourceField=["Attention"] -- which names
      no real form field -- this platform gates the attribute out of serialization,
      so Attention never reaches the wire (HI v2.4 T9: DriverHistoryQuery omitted
      Attention). Neither importable config makes the handler emit. Net: the
      auto-Attention handler is effectively INERT on ConnectCic. Treat Attention
      auto-populate as a platform limitation / escalate to Cringer before relying
      on it. Do NOT switch sourceField to [] to "fix" it -- that only breaks import.

  --------------------------------------------------------------------------
  14. IgnoreUserValueRuleHandler
  --------------------------------------------------------------------------
      Config type:  QIDM attribute
      Arguments:    list of values to ignore (case-insensitive)
      Purpose:      Filters unwanted values -- returns null if value matches
                    any configured ignore code, otherwise returns original value
      Source:       CA_ESUN template only
      All builds:   NO
      Status:       DEAD END for state hardcoding (AP #4)

      Behavior:
        - Reads sourceField value from userArguments
        - Compares against arguments list (case-insensitive)
        - If match found: returns null (suppresses the field)
        - If no match: returns original value unchanged

      Example: arguments=["UNK","XXX","000"]
        Input "BLU" -> "BLU" (passed through)
        Input "UNK" -> null  (filtered out)
        Input "unk" -> null  (case-insensitive)

      WHY AP #4 (dead end for state hardcoding): This handler FILTERS values
      but does NOT SUBSTITUTE them. Cannot use it to replace a user value with
      a hardcoded state code. Use InpH with initialValue instead.

  --------------------------------------------------------------------------
  15. CommsysArticleAttributeRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (ArticleTypeCode, ArticleCategory, etc.)
      Arguments:    [mode, optional-alt-key]
                    mode: "FIRST_CHAR" (default) or "REMAINDER"
                    alt-key: alternative key in userArguments (overrides sourceField)
      Purpose:      Extracts first character or remainder of an article code
      Source:       _build_rms_bundle.ps1 (QRDM) + _build_provider_helpers.ps1 (CommSys QRDM)
      All builds:   YES (in QRDM via shared modules)

      Examples (input "JE123"):
        FIRST_CHAR -> "J"
        REMAINDER  -> "E123"
      Single character input "X":
        REMAINDER  -> "" (empty string)

      Config (first char):
        {
          "name": "ArticleCategory",
          "rule": { "function": "CommsysArticleAttributeRuleHandler",
                    "arguments": ["FIRST_CHAR"] },
          "sourceField": ["ArticleCode"],
          "targetField": "ArticleCategory"
        }

================================================================================
  RULE HANDLERS -- QRDM (inbound result parsing)
================================================================================

  These are attribute-level handlers on QRDM attributes. They transform
  CommSys response data into display values. All built by shared modules.

  --------------------------------------------------------------------------
  16. CommsysResultAttributeMappingRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (primary rule)
      Arguments:    none (uses additionalFields on the attribute)
      Purpose:      Maps a raw code to a display value using system attribute tables
      Source:       Shared modules (QRDM config)
      All builds:   YES -- used on State, Sex, Race, Eye, Hair, Color, Make, Style

      Required additional fields on attribute:
        codeTypeSource:   code source identifier (e.g. "NCIC")
        + ONE of:
          codeTypeCategory: category for AttributeSource lookup
          attributeType:    type for AttributesDataMapping lookup

      Operation modes:
        If codeTypeCategory present -> lookup via AttributeSource (by code or description)
        If attributeType present    -> lookup via AttributesDataMapping (code -> link -> type -> display)

      Returns null if code not found. Lookup is case-insensitive and also
      accepts a description as input.

      Config:
        {
          "name": "AddressStateCode",
          "rule": { "function": "CommsysResultAttributeMappingRuleHandler" },
          "sourceField": ["AddressStateCode"],
          "targetField": "AddressStateCode",
          "attributeType": "STATE",
          "codeTypeSource": "NCIC"
        }

  --------------------------------------------------------------------------
  17. CommysResultFallbackRegexRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (fallbackRule only)
      Arguments:    chained directives (processed in order)
      Purpose:      Extracts values from free-text (messageData) via regex
      Source:       Shared modules (QRDM config)
      All builds:   YES -- paired with primary rules as fallback
      Note:         Typo in name (Commys not Commsys) is correct -- do not fix

      Reads userArguments["messageData"] as the text source.
      Iterates over regex patterns in order -- returns the first match.
      Then applies configured transformations to the result.

      Argument directives:
        "regex:<pattern>"   Regex pattern (multiple allowed, tested in order)
        "uppercase"         Converts result to uppercase
        "lowercase"         Converts result to lowercase
        "maxLength:<n>"     Truncates result to N characters
        "rule"              After extraction, execute the primary rule handler on result

      Config:
        {
          "name": "LicensePlate",
          "rule": { "function": "CommsysGetStateCodeRuleHandler" },
          "fallbackRule": {
            "function": "CommysResultFallbackRegexRuleHandler",
            "arguments": [
              "regex:LIC/([A-Z0-9]{1,8})/",
              "regex:PLATE:\\s*([A-Z0-9]+)",
              "uppercase",
              "maxLength:8",
              "rule"
            ]
          },
          "sourceField": ["LicensePlate"],
          "targetField": "LicensePlate"
        }

  --------------------------------------------------------------------------
  18. HeightParserRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (Height, HeightFeet, HeightInches, HeightDisplay)
      Arguments:    [field-list, output-type]
                    field-list: ["Height"] for Commsys, ["HeightFeet","HeightInches"] for RMS
                    output-type: "height" (default), "feet", "inches", "total"
      Purpose:      Normalizes height values from Commsys (3-digit) or RMS formats
      Source:       Shared modules (QRDM + RMS Results)
      All builds:   YES

      Output types:
        "height"  -> display format "5' 9""
        "feet"    -> feet only "5"
        "inches"  -> inches only "9"
        "total"   -> total inches "69"

      Commsys 3-digit format: "509" -> 5 feet 9 inches
      RMS two-field format: HeightFeet="5", HeightInches="9"

  --------------------------------------------------------------------------
  19. ParseCommsysNameRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (NameFirst, NameLast, NameMiddle, Name)
      Arguments:    4 arrays defining 3-level fallback + separators
                    [0]: normalized parts keys [last, first, middle]
                    [1]: combined normalized name keys
                    [2]: common name keys
                    [3]: separators for building full Name field
      Purpose:      Parses and resolves name fields with 3-level fallback
      Source:       Shared modules (QRDM config)
      All builds:   YES
      Note:         Returns different fields based on attribute.name value
                    (NameFirst, NameLast, NameMiddle, or Name)

      Resolution priority (tries each level until one produces a result):
        1. Normalized parts (NormalizedNameLast + NormalizedNameFirst)
        2. Combined normalized name (NormalizedName) -- parsed by comma/space
        3. Common name (Name) -- same parsing as step 2

      Combined name parsing rules:
        With comma:    "DOE, JOHN Q"          -> last=DOE, first=JOHN, middle=Q
        3 tokens:      "SMITH JOHN MICHAEL"   -> last=SMITH, first=JOHN, middle=MICHAEL
        Last tok 1chr: "DOE JOHN Q"           -> last=DOE, first=JOHN, middle=Q
        Comma no space:"MAYES,JEFFERY SCOTT"  -> last=MAYES, first=JEFFERY, middle=SCOTT

      Supersedes FormatNameRuleHandler (deprecated).

  --------------------------------------------------------------------------
  20. ParseCommsysVehicleYearRuleHandler
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (VehicleYear)
      Arguments:    [threshold] (integer, e.g. 50)
      Purpose:      Normalizes 2-digit vehicle years to 4-digit using threshold
      Source:       Shared modules (QRDM config)
      All builds:   YES

      Expansion logic (4-digit years returned unchanged):
        yy < threshold  -> 2000 + yy  (e.g. 25 -> 2025)
        yy >= threshold -> 1900 + yy  (e.g. 75 -> 1975)

  --------------------------------------------------------------------------
  21. truncate
  --------------------------------------------------------------------------
      Config type:  QRDM attribute (SocialSecurityNumber)
      Arguments:    none (uses size property on attribute)
      Purpose:      Truncates field value to attribute size
      Source:       Shared modules (QRDM config)
      All builds:   YES
      Note:         Lowercase name -- not a typo

  --------------------------------------------------------------------------
  22. FormatArrayRuleHandler
  --------------------------------------------------------------------------
      Config type:  RMS QRDM attribute (Cautions, WarrantDetails, Addresses, etc.)
      Arguments:    [source-field-paths, target-field-names]
                    Supports dot notation and brackets for nested arrays
      Purpose:      Transforms nested JSON arrays using declarative field mapping
      Source:       _build_rms_bundle.ps1 (RMS Results)
      All builds:   YES

      Nested field syntax:
        Source: "warrantCharges[chargeName,chargeCount]"
        Target: "Charges[Name,Count]"
        Maps nested array fields to renamed target fields.

      Input is a JSON string in userArguments (key from sourceField[0]).

  --------------------------------------------------------------------------

  --------------------------------------------------------------------------
      Config type:  RMS QRDM attribute (Name)

      Purpose:      Formats name fields from RMS response
      Source:       _build_rms_bundle.ps1 (RMS Results)

================================================================================
  CODE MAPPING HANDLERS (response-side)
================================================================================

  These handlers map Commsys response codes to Federated Search internal codes
  using static configuration lists. All are response-side (QRDM) only.
  All built by shared modules -- no build script action needed.

  Handler                              | Maps           | Static Config
  -------------------------------------|----------------|------------------
  CommsysGetArticleCodeRuleHandler     | Article codes  | articleCategoryCodes
  CommsysGetRaceCodeRuleHandler        | Race codes     | raceCodes
  CommsysGetSexCodeRuleHandler         | Sex codes      | sexCodes
  CommsysGetStateCodeRuleHandler       | State codes    | stateCodes
  CommsysGetLicensePlateCodeRuleHandler| Plate types    | licensePlateTypeCodes
  CommsysGetVehicleCodeRuleHandler     | Vehicle codes  | articleCategoryCodes (shared)

  All take List<String> input, use first element as code.
  Return mapped code or null if not found.

================================================================================
  DEAD ENDS / DO NOT USE
================================================================================

  IgnoreUserValueRuleHandler -- AP #4. Does not SUBSTITUTE values.
    Returns null for matching codes, original value for non-matching.

    a different one. Use InpH with initialValue for hardcoded defaults.

================================================================================
  BUILD SCRIPT CHECKLIST
================================================================================

  Every QIDM must have:    handlerFunction = 'CommsysTransactionRequestHandler'
  BirthDate attrs:          rule.function = 'CommsysParseDateRuleHandler'
  Name attrs:               rule.function = 'FormatStringRuleHandler'
  Auth config:              handlerFunction = 'CommsysOriAuthenticationHandler'
  QMF config:               handlerFunction = 'CommsysWsiOutgoingMessageHandler'
  QRDM config:              handlerFunction = 'CommsysResultsHandler'

  All RMS/Auth/QMF/QRDM handlers are set by the shared modules.
  Build scripts only need to explicitly set handlers on QIDM attrs they create.
