DEVELOPER TOOLS — ConnectCIC Provider JSON Development
========================================================
Last updated: 2026-04-23

Tools required for building, validating, and testing provider JSON configurations.
All developers working on provider JSONs should have these installed.

========================================================
1. PREREQUISITES (system-level)
========================================================

1a. Git for Windows (includes Git Bash + MinGW tools)
    Install: https://gitforwindows.org/
    Provides: bash, git, pdftotext (via MinGW), standard Unix utilities
    Verify:  git --version

1b. PowerShell 5.1+ (included with Windows)
    Note: Scripts require -ExecutionPolicy Bypass when run from CLI:
      powershell -ExecutionPolicy Bypass -File <script>.ps1
    Verify:  powershell -Command "$PSVersionTable.PSVersion"

1c. pdftotext (included with Git for Windows MinGW)
    Location: /mingw64/bin/pdftotext (accessible from Git Bash)
    Purpose:  Extract devdoc PDF text for cross-referencing metadata
    Usage:    pdftotext "source/<Provider>.pdf" "source/<PROVIDER>_DEVDOC.txt"
    Verify:   pdftotext -v  (from Git Bash)
    If missing: install poppler-utils (choco install poppler OR winget install poppler)

========================================================
2. BUILD & VALIDATION TOOLS (provider-agnostic scripts)
========================================================

All tools are in C:\Users\RobSgambellone\.local\bin\
Run from that directory or use full paths.

2a. build_report.ps1 — Master build report (runs all 5 tools below)
    Usage:  powershell -ExecutionPolicy Bypass -File build_report.ps1 -Path "<PROVIDER>\<FILE>.json"
    Output: 5 reports in <PROVIDER>/docs/base/ (or docs/mc/)
    Flags:  -Release bundles JSON + all reports to release/ folder
    Run:    After EVERY JSON build or edit. Do not wait to be asked.

2b. validate.ps1 (via connectcic-validator/)
    Usage:  powershell -ExecutionPolicy Bypass -File connectcic-validator/validate.ps1 -Path "<FILE>.json"
    Checks: 6-phase validation (encoding, bundles, QIF layout types, QIDM refs, autoSelect, combos)
    Target: 0 FAIL before any import. Calibrated against NJ baseline.

2c. render_layout.ps1 — Layout text tree renderer
    Usage:  powershell -ExecutionPolicy Bypass -File render_layout.ps1 -Path "<FILE>.json"
    Flags:  -Summary (overview only), -Entity <name> (filter), -Variant <type>, -QidmOnly
    Output: Text tree showing QIF card/row/field structure

2d. test_commsys.ps1 — CommSys query simulator
    Usage:  powershell -ExecutionPolicy Bypass -File test_commsys.ps1 -Path "<FILE>.json"
    Flags:  -Entity <name> (filter), -Combo <keyRef> (filter)
    Output: Which combos fire given test data, plus simulated XML output
    Note:   Edit $testData in script to change form values

2e. report_picklists.ps1 — Picklist/code type scanner
    Usage:  powershell -ExecutionPolicy Bypass -File report_picklists.ps1 -Path "<FILE>.json"
    Output: All FormSelect dropdowns + QRDM/QIDM code types for audit

2f. render_html.ps1 — HTML layout renderer
    Usage:  powershell -ExecutionPolicy Bypass -File render_html.ps1 -Path "<FILE>.json" -OutFile "<out>.html"
    Output: Self-contained HTML with color-coded fields, QIDM tables, combo priority

========================================================
3. BUILD SCRIPTS (per-provider)
========================================================

Each provider has its own build script in <PROVIDER>/scripts/:

    powershell -ExecutionPolicy Bypass -File scripts/build_<provider>.ps1

Build scripts generate the provider JSON from code. Always rebuild from
the script — never hand-edit the JSON directly.

After running the build script, ALWAYS run build_report.ps1 (Section 2a).

========================================================
4. REFERENCE FILES
========================================================

4a. ConnectCIC-KB/knowledge-base/ — Central knowledge base (11 docs)
    READ BEFORE EVERY SESSION. See README.txt for index.

4b. ConnectCIC-KB/templates/HIDLE.json — RMS/AUTH base template
    Clone and patch per provider. Never modify the template directly.

4c. <PROVIDER>/source/<PROVIDER>.XML — XML metadata (primary build authority)
    When metadata and devdoc disagree, metadata wins.

4d. <PROVIDER>/source/<PROVIDER> devdoc.pdf — CommSys devdoc
    Supplementary reference for field details, M/C/O status, valid values.
    Extract to text: pdftotext "source/<file>.pdf" "source/<PROVIDER>_DEVDOC.txt"

========================================================
5. STANDARD WORKFLOW
========================================================

  1. Read KB (knowledge-base/README.txt + CLAUDE.md)
  2. Extract devdoc PDF to text (pdftotext)
  3. Cross-reference devdoc against XML metadata
  4. Write/update build script
  5. Run build script → generates provider JSON
  6. Run build_report.ps1 → generates 5 reports
  7. Verify: 0 FAIL, all combos FIRE
  8. Commit JSON + reports + build script to git
  9. Import to test instance
 10. Run 4-phase live test suite

========================================================
6. FOLDER STRUCTURE (per provider)
========================================================

  <PROVIDER>/

    docs/
      base/                       — BASE build reports (5 files)
      mc/                         — MC build reports (5 files)
    phases/
      base/                       — BASE version snapshots
      mc/                         — MC version snapshots
