NJ_NJCJIS -- New Jersey
================================================================================

NJ-1: VehicleStolenQuery registered separately
  NJ CommSys has VehicleStolenQuery as a distinct transaction. Vehicle QIDM covers
  VehicleRegistrationQuery; a second QIDM covers VehicleStolenQuery. Both target
  the same Vehicle entity but different query values, so LIMITATION #2 does not apply.
  RandomRequest (Y/N): RAND combo = stolen-only (Y), FULL combo = all-data (N).

NJ-2: State initialValue='NJ' is safe
  NJ has no separate in-state vs OOS keyRefs. State is always in set[] for primary
  combos. initialValue='NJ' does not change which combo fires (unlike NY -- see
  PLATFORM_CONSTRAINTS.txt #30). Safe to default.

NJ-3: BirthDate format MMddyyyy
  CommSys expects: CommsysParseDateRuleHandler arguments=['yyyy-MM-dd','MMddyyyy']

NJ-4: AUTH keyReference and RMS autoSelect in build script
  AUTH keyReference and RMS Person+Vehicle autoSelect=true must be in build script
  (not applied manually post-build). Confirmed fixed in v2.3 build script.

NJ-5: Confirmed attribute IDs (from live test)
  NJ state: 69509884952, PA state: 69509887513, NY state: 69509888105
  Male sex: 69509891711, Female sex: 69509894381, Unknown sex: 69509886562

FL_FCIC -- Florida
================================================================================

FL-1: Entity-split BLOCKED (LIMITATION #28)
  FL originally used Person-FL + Person-OOS split. codeTypeProvider reverse-lookup
  breaks with multiple Person QIFs (duplicate targetField). Redesigned to single
  6-card Person QIF (v2.2+). Do NOT attempt entity-split on FL.

FL-2: FL-specific transaction keys
  FL uses FCIC keys: FRQ (vehicle reg), FDQ (driver license), QW (firearm),
  KQ (driver history), FBQ (boat stolen). Mixed with NCIC/Nlets keys in same
  transactions.

FL-3: DriverHistoryQuery (KQ) is FL-specific
  KQ includes PurposeCode (FormInput, maxLength=1, initialValue='C').
  Not all providers have DH -- check metadata.

FL-4: Boat combo priority conflict (RESOLVED -- see FL-8)
  QB+Hull and QB+Reg were unreachable due to FBQ combos firing first.
  RESOLVED 2026-05-05 via RelatedHitSearchIndicator routing (FL-8).
  All 12 boat combos now reachable. Live tested 13/13 PASS.

FL-5: BoatHullIdNumber maxLength=62
  Longer than NJ standard (20). Provider-specific metadata value.

FL-6: VehicleRegistrationQuery has no State requirement
  FL vehicle reg is in-state only. State not in metadata for this query.
  Do NOT add State to vehicle combos unless metadata includes it.

FL-7: DL+DH shared form (6-card design)
  Uses LIMITATION #24/#25 pattern: autoSelect + queriesToDeselect + DH-suffix fieldIds.
  Reference implementation for shared-form DL+DH.

FL-8: BoatQuery QB+Hull/QB+Reg routing via RelatedHitSearchIndicator
  QB+Hull and QB+Reg were unreachable because FBQ+Hull/FBQ+Reg shared the
  same set[] field and fired first. Fixed: RelatedHitSearchIndicator
  (metadata field, Y/N, exclusive to QB combos) promoted from any[] to set[]
  on QB+Hull and QB+Reg. Officer types Y in "Stolen Search" to route to NCIC
  stolen; blank = FL registration (FBQ). QB combos ordered before FBQ.
  Fallback tag: FL_FCIC_PRE_QB_ROUTING (revert if server rejects field).

FL-9: Sex reverse-lookup works (single-QIF only)
  codeTypeProvider='NIBRS' reverse-lookup works on FL instance when using single
  Person QIF. Prior "FL doesn't support reverse-lookup" was wrong — actual failure
  was duplicate targetField from entity-split design (FL-1). Confirmed 2026-04-20.

FL-10: DriverHistoryQuery (KQ) is OOS-only by devdoc -- not a platform limitation
  FCIC confirmed 2026-06-12: "DriverHistoryQuery requires destination <XX> which must
  be non-FL." FL-in-state DH queries are blocked by design; no in-state KQ combo exists.
  CAD cannot supply a destination state -> DH never auto-fires from CAD (expected).
  NOTE: NOT_EQUALS conditions cannot enforce the home-state block programmatically
  (poisoned-array rule -- LIMITATION #37 -- makes value-comparison conditions inert on
  this instance). Devdoc authority is the gate; no workaround needed.

NY-4: DriverHistoryQuery Name path blocked

  Invented DALH keyRef resolves duplicate keyRef issue.
  DH co-fires with DL on OLN entry = correct workflow.

NY-5: BirthDate format MMddyyyy
  Same as NJ. Arguments=['yyyy-MM-dd','MMddyyyy']

NY-6: RaceCode NIBRS_RACE/NIBRS confirmed
  codeTypeSource=NCIC gave empty dropdown. Fixed to NIBRS source.

NY-7: BoatQuery and DriverHistoryQuery are ACTIVE
  Both transactions exist in metadata with full XML definitions.
  BoatQuery: 4 combos (RVEH/RCAR in-state, BVEH/BVIN OOS). Confirmed live.

HI_HCJDC_OFML -- Hawaii
================================================================================

HI-1: VehicleTypeCode uses HI_NIBRS source
  codeTypeCategory='VEHICLE_TYPE', codeTypeSource='HI_NIBRS'.
  NCIC source = empty dropdown.

HI-2: Vehicle ImageIndicator in combo any[]
  ImageIndicator must be in Vehicle QIDM combination any[] arrays for
  serialization. Fixed in v1.1 build script.

HI-3: Empty any[] pattern
  HI combos use empty any[] arrays (all optional fields omitted from combo).
  Correct -- fields still serialize via LIMITATION #1 (all populated
  attrs sent regardless of any[]).

HI-4: 6-transaction build from XML metadata
  VehicleRegistrationQuery, DriverLicenseQuery, DriverHistoryQuery, GunQuery,
  ArticleSingleQuery, BoatQuery. Standard 5-entity + DH.
  No VehicleStolenQuery in metadata.

HI-5: NCIC state and SexCode unconfirmed
  Both need first-import testing. Default to standard pattern, verify on import.

HI-6: KQN (DriverHistoryQuery Name combo) fires on OLN alone -- RegistrationState is any[]
  T26 v4.0 confirmed: KQN fires when only OperatorLicenseNumberDH is entered. RegistrationState
  is in any[] on KQN (not set[]) -- State is absent from the wire when blank; KQN has no
  State requirement. This differs from the DL pattern where RegistrationState IS in set[]
  on OLN combos. Do NOT assume DL and DH have the same set[]/any[] structure for State.
  Generalizable pattern: DH OLN combos may carry State as optional (any[]) even when DL OLN
  combos require it (set[]). Verify per-entity; don't copy DL combo set[] verbatim to DH.

CA_CLETS -- California
================================================================================

CA-1: CaRequestPurposeCode on every form and combo
  Hidden initialValue='C' on all 5 entity forms, in set[] on every combo.
  California-specific requirement (not in any other provider).

CA-2: State initialValue must NOT be set (LIMITATION #30)
  CA has separate in-state (IA.*) vs OOS (NLTS.*) keyRefs. State presence
  routes between them. Same constraint as NY (NY-2).

CA-3: BirthDate format yyyyMMdd
  Different from NJ (MMddyyyy). Same as AZ. Confirmed from CA_ESUN production.
  Arguments=['yyyy-MM-dd','yyyyMMdd']

CA-4: No ImageIndicator
  CA metadata does not include ImageIndicator on any transaction.
  Do NOT add ImageIndicator to CA forms or combos.

CA-5: 6 basic queries only (devdoc authority)
  Devdoc "Basic Queries Supported" lists 6 queries. Metadata contains additional
  transactions (WP, MP, SupervisedRelease) that are NOT authorized to build.
  CAILojackQuery is devdoc "Expanded" only.

CA-6: DL+DH co-fire (2 Person QIDMs)
  Both DL and DH have autoSelect=true with no queriesToDeselect. DL+DH always
  fire together. This is the standard CA police workflow.

CA-7: ArticleTypeCode uses CA_CLETS source
  codeTypeCategory='NCIC_ARTICLE_TYPE', codeTypeSource='CA_CLETS'.
  NCIC source gives empty dropdown.

CA-8: MC cross-entity combos
  3 MC-only combos add person fields to non-person entity forms:
  IN.VP (Vehicle by Name), IG.QGH (Gun by Name), NLTS.BQ.N (Boat by Name+DOB).

================================================================================
CROSS-PROVIDER CONSISTENCY RULES
================================================================================

These patterns MUST match across all providers. Differences require metadata
justification documented in the provider's section above.

1. RMS autoSelect=true on all RMS QIDMs
   Confirmed: all 20 providers.

2. AUTH keyReference present
   Confirmed: all 20 providers.

3. ImageIndicator in combo any[] or set[]
   Must be in at least one combo per entity where it appears on the form.
   Exception: CA (no ImageIndicator in metadata — CA-4).

4. queryLabel standard values
   Vehicle Registration, Vehicle Stolen, Driver License, Driver History, Firearm, Article, Boat,
   Wanted Person, Missing Person, RMS.
   All providers must use these exact labels.

5. PlateType default=PC, PlateYear default=current year
   Confirmed: all 20 providers (2026-05-06). Mandatory standard.
   Safe: State is combo routing discriminator, not PlateType/Year.

6. YES_NO_UNKNOWN/NCIC for all Y/N dropdowns
   No provider should use YES_NO, YESNO, or other variants.

7. Patch 8: LicensePlateNumberIn eliminated from all output JSONs
   CAD sends licensePlateNumber (camelCase, no "In" suffix).
   Confirmed: all 20 providers.

8. BirthDate format is provider-specific
   MMddyyyy: NJ, NY, TX, LA, HI, IL, MD, OH, NM
   yyyyMMdd: AZ, FL, CA_CLETS, CA_VENTURA_COUNTY, CA_CLETS_OCATS, CA_SAN_LUIS_OBISPO, OR, TN
   MIXED:    CA_eSUN (yyyyMMdd primary, MMddyyyy for GunQuery)
   NEVER copy date format from another provider. Verify from build script or metadata.
