================================================================================
  4. IgnoreUserValueRuleHandler -- CORRECTED ENTRY (supersedes the old "DEAD END" note)
================================================================================
  BEHAVIOUR (platform doc): returns NULL when the value is in the ignore list, otherwise returns
  the value unchanged. Match is CASE-INSENSITIVE. It filters; it cannot SUBSTITUTE one value for
  another.
    sourceField[0]   the key to read
    rule.arguments   the list of values to ignore

  PRODUCTION USE -- CA_eSUN (from the deployed department export, 2026-07-29):
    { "name":"State", "rule":{ "function":"IgnoreUserValueRuleHandler","arguments":["CA"] },
      "size":4, "sourceField":["RegistrationState"], "targetField":"State" }
  applied on VehicleRegistrationQuery, DriverLicenseQuery, DriverHistoryQuery AND BoatQuery.
  Purpose: the form/CAD always supplies the home state (deployed eSUN's RegistrationState is a
  FormSelect with initialValue='CA'), and this drops "CA" so an in-state query does not send
  State=CA to a California system.

  RULE_HANDLERS.txt previously listed this under "DEAD ENDS / DO NOT USE" as a dead end "for state
  hardcoding". That is correct ONLY for hardcoding (it cannot inject a value). It is NOT a dead end
  for STRIPPING a home state -- that is exactly what production uses it for. Corrected 2026-07-29.

  *** OPEN QUESTION -- PARTIALLY NARROWED, STILL NOT SETTLED (DEX-1284, 2026-08-06) ***
  STATUS: HYPOTHESIS (discriminating test now needs a LIVE tenant, not just a simulator --
  see below for exactly why the simulator cannot finish this one).

  MECHANICAL PART -- CONFIRMED (scratch-copy simulator test, NY_NYSPIN_EJUSTICE v4.21, throwaway
  mutation, not committed): added `IgnoreUserValueRuleHandler(["NY"])` to the `State` attribute of
  VehicleRegistrationQuery, filled RegistrationState="NY" (CAD-style home-state autofill on a plate
  query). Result: combo selection is UNCHANGED -- `RVEHOUT` (the OOS combo) still fires, because its
  `RegistrationState EXISTS` condition reads the raw FORM value before the handler runs. The wire's
  `<State>` element is fully OMITTED (not blank -- absent), and RVEHOUT's own combo defaults
  (LicensePlateTypeCode=PC, LicensePlateYear=<current>) still ride along since they are unconditional
  defaults, not value-gated. This confirms _sim_helpers' documented ordering (conditions read FORM
  STATE; rule handlers only transform the OUTBOUND value) -- that part is settled.

  WHAT IS *NOT* SETTLED -- and a simulator structurally cannot settle it: whether the real CommSys
  server treats "OOS-shaped request, State absent, PlateType+Year present" as a CORRECT in-state
  NCIC lookup or a MALFORMED OOS request. LIMITATION #37 (PLATFORM_CONSTRAINTS.txt) established that
  for value-comparison conditions, the SERVER -- not our combo keyReference -- picks the real message
  key from field VALUES it receives (CA_CLETS IA.QV: "no State -> IA.QV fires" server-side, regardless
  of which combo our own config record says fired). If that same server-side value-driven selection
  applies here, a State-absent wire could resolve correctly to an in-state lookup DESPITE our internal
  combo saying "RVEHOUT" -- the internal keyReference is proven elsewhere to be informational only,
  never transmitted. Our simulator has no knowledge of the live server's actual selection logic, so it
  cannot distinguish "this works" from "this is worse than today." Only a real tenant capture can.
  Same applies to FL, TX, CA_CLETS, HI, OH, MD, NM, OR, TN (all condition-gated on
  RegistrationState EXISTS/NOT_EXISTS) -- do not generalize this to any of them without their own test.

  Deployed eSUN does not settle this either: its combos carry NO conditions at all and route purely
  by set[] membership, so the handler never has to influence routing there -- its case is simpler
  than any condition-gated provider's.
  IMPLICATION: adopting the eSUN pattern on a condition-gated provider is a ROUTING-MODEL question
  whose outcome is unknown until tested live, not a one-line handler addition to copy blind.

================================================================================
  6. DEPLOYED CA_eSUN vs OUR CA_eSUN v2.0 -- known deltas (2026-07-29)
================================================================================
  Ours is a galvanization rebuild and differs from what is actually deployed:
    - deployed has IgnoreUserValueRuleHandler(["CA"]) on State (Veh/DL/DH/Boat); ours has none,
      so OUR build would send State=CA to a California system on an in-state query
    - deployed has CommsysArticleAttributeRuleHandler on ArticleCategory/ArticleTypeCode
    - deployed RegistrationState is a FormSelect initialValue='CA' label 'State';
      ours has no default, label 'State (leave blank for CA)'
    - deployed combos carry NO conditions and route by set[] membership;
      ours uses existence-gated conditions
    - deployed combos carry an ORI field in any[]; ours do not
    - deployed carries the top-level behaviors block
  DO NOT "fix" our eSUN to match without a decision: the two designs are coherent but different,
  and switching routing models invalidates that provider's whole test package.
