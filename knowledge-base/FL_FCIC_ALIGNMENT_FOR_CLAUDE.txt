6. CONFIRMED BUGS -- MUST FIX BEFORE IMPORT
================================================================================

  BUG #1 -- SexCode uses attributeTypeId='SEX' (CONFIRMED BUG)
  -----------------------------------------------------------------
  Location: build_fl_fcic.ps1 line ~928:
      Sel 'SexCode' 'Sex' @{ attributeTypeId = 'SEX' } 'ROW_3'

  Also in:
    - change8_instate_subcards.ps1 (InState form)
    - change9_oos_subcards.ps1 (OOS form, SexCodeOOS)
    - change12_add_person_dh.ps1 (DH form, SexCodeDH)

  What it does wrong:
    attributeTypeId='SEX' causes the platform to send the internal numeric
    attribute ID instead of the human-readable sex code (M/F/U).
    The outbound XML receives a number like "69509884952" instead of "M".

  Fix (apply everywhere SexCode appears):
    Remove: @{ attributeTypeId = 'SEX' }
    Add:    @{ codeTypeCategory = 'NIBRS_SEX'; codeTypeSource = 'NIBRS' }

  This was fixed in both NJ_NJCJIS and NY_NYSPIN_EJUSTICE. Same bug.
  See KB: PLATFORM_LIMITATIONS.txt #19, ANTI_PATTERNS.txt #2, FIELD_RULES.txt

  BUG #2 -- queriesToDeselect confirmed ineffective (PLATFORM-WIDE)
  -----------------------------------------------------------------
  v1.4 added autoSelect + queriesToDeselect to DL/DH mappings.
  Platform live testing (NY v1.15/v1.16) confirmed: queriesToDeselect
  CANNOT prevent co-fire. Platform evaluates all matching QIDMs simultaneously
  from a shared field pool BEFORE deselect can intercept.

  Current state: v1.4 has queriesToDeselect on ALL 4 DL/DH QIDMs.
  Correct design (NY baseline): remove queriesToDeselect from DL QIDMs;
  keep on DH QIDM only (no isolation benefit but no harm).

  See KB: PLATFORM_LIMITATIONS.txt #26, QIDM_ARCHITECTURE.txt Scenario B,
          ANTI_PATTERNS.txt #14 and #16.

11. FL-SPECIFIC DESIGN DECISIONS (do not change without understanding why)
================================================================================

  Vehicle RegistrationState -- NO initialValue:
    Blank = FL-only (FRQ fires); filled = out-of-state (RQ fires).
    NJ/NY use dual-field state (SelH hidden + InpH initialValue). FL does NOT --
    FL uses a visible State dropdown, blank=FL, no hidden state needed.
    Reason: FRQ+RQ routing controlled by whether State is populated.
    DO NOT add initialValue='FL' unless you confirm this doesn't break RQ routing.

  BoatHullIdNumber maxLength=62:
    FL spec specifies 62-char hull ID. NJ/NY use shorter. Do not shorten.

  GunCaliber: NOT in FL_FCIC.xml spec:
    FL XML has no GunCaliber field. NJ has it as FormInput. Do not add.

  KQ (Driver History) requires State:
    KQ always sends State=FL. Person form has RegistrationState with default FL.
    If entity split moves DH to its own form, that form needs State populated.

  FIRST_RESPONDER layout:
    FL_FCIC includes FIRST_RESPONDER as a third layout variant alongside
    default and CAD_DISPATCH. Platform recognition of FIRST_RESPONDER as a
    key is UNCONFIRMED. NJ/NY also include it. Do not remove until confirmed.

  Article: codeTypeSource=CA_CLETS (same as all providers):
    NCIC_ARTICLE_TYPE lives under CA_CLETS, not NCIC. Confirmed platform-wide.
    See KB PLATFORM_LIMITATIONS.txt #17.

  BoatQuery keyRef disambiguation:
    BQ vs BQN are shared with VehicleRegistrationQuery in some providers.
    FL uses FBQ+QB -- no disambiguation conflict. This is FL-specific.
