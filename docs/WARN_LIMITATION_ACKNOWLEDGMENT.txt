--- COMBO PRIORITY ORDER (appears on all providers with DL/DH/VehicleReg) ---

  L-PRIORITY: "combo order has fewer set[] fields before more"
    Meaning: OLN combo (1-2 set[] fields) ordered before Name combo (3-5 set[] fields).
    Justification: Operational priority -- officers search by OLN first, Name second.
    First matching combo fires (LIMITATION #3). OLN before Name is correct workflow.
    Appears on: NJ(1), NY(2), FL(3), AZ(2), HI(3) = 11 instances across BASE variants.
    Status: ACKNOWLEDGED -- by design.

--- VEHICLE DUAL QIDMs / NO queriesToDeselect (LIMITATION #24) ---

  L-VEHICLE-QTD: "2 QIDMs on 1 QIF but none have queriesToDeselect"
    Meaning: VehicleRegistration + VehicleStolen share one Vehicle form.
    Justification: RandomRequest (NJ) or field routing gates co-fire. Both queries
    should fire simultaneously. queriesToDeselect would break co-fire.
    Appears on: NJ BASE+MC, FL BASE+MC = 4 instances.
    Status: ACKNOWLEDGED -- by design (LIMITATION #24).

--- PERSON DL+DH CO-FIRE AUTOSELECT ---

  L-DL-DH-COFIRE: "2 QIDMs have autoSelect=true on a SINGLE QIF"
    Meaning: DL and DH both auto-check when person data is entered.
    Justification: Standard police workflow -- officer enters OLN, gets both DL and DH.
    Appears on: NY BASE+MC, FL MC, AZ BASE+MC = 5 instances.
    Status: ACKNOWLEDGED -- by design.

--- PERSON NO queriesToDeselect (LIMITATION #24) ---

  L-PERSON-QTD: "QIDMs on 1 QIF but none have queriesToDeselect"
    Meaning: Multiple Person QIDMs share one form without mutual deselect.
    Justification: Shared field pool (LIMITATION #26) makes queriesToDeselect
    ineffective. Co-fire is the correct behavior.
    Appears on: NY BASE+MC, AZ BASE+MC = 4 instances.
    Status: ACKNOWLEDGED -- platform constraint.

--- DL+DH NO DH-SUFFIX FIELDIDS (AP #14 / LIMITATION #25) ---

  L-NO-DH-SUFFIX: "DL + DH QIDMs on single form without DH-suffix fieldIds"
    Meaning: DH uses same fieldIds as DL (shared field pool).
    Justification: NY and HI intentionally use shared fields -- DH co-fires with
    DL on OLN entry. DH-suffix pattern (FL) is an alternative for isolation.
    Appears on: NY BASE+MC, HI BASE+MC = 4 instances.
    Status: ACKNOWLEDGED -- known constraint, DH co-fire is acceptable.

--- STATE NO initialValue (LIMITATION #30) ---

  L-STATE-DEFAULT: "State has NO initialValue"
    Meaning: State dropdown is blank by default.
    Justification: Provider has separate in-state (e.g., RCAR) vs OOS (e.g., RVIN)
    keyRefs. Setting a default would cause OOS combos to fire for in-state queries.
    Blank default preserves correct query type routing.
    Appears on: NY BASE+MC (explicit), FL BASE+MC (implicit -- no State on VehicleReg).
    Status: ACKNOWLEDGED -- by design (LIMITATION #30).
